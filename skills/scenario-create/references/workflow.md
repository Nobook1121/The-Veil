# 剧本创作通用流程

这份流程只讲“如何和用户一起把想法变成可导入的剧本包”，不绑定任何规则集。
具体的规则口径、数值、职业/技能体系与创作禁忌由当前规则集插件提供。

## 1. 先确认创作简报

一次只问一组问题，避免让用户一次回答十几个点：

| 维度 | 需要确认的内容 |
| --- | --- |
| 主题 | 想写什么故事、核心冲突、最想出现的场面 |
| 世界 | 时代、地点、现实/奇幻/科幻、已有设定或原创 |
| 玩家 | 人数、角色强度、入场方式、彼此关系 |
| 基调 | 调查、恐怖、动作、悬疑、喜剧、悲剧 |
| 时长 | 单次、2–3 次、长线；每次大约多久 |
| 结局 | 成功/失败/妥协/开放；是否允许角色死亡 |
| 红线 | 不能出现的题材、描写尺度、玩家禁忌 |

用户没有想法时给 2–3 个可选方向，不要替用户做关键决定。

## 2. 一页大纲

在写正文前，先给一页大纲让用户确认：

```
钩子 → 初步探索/调查 → 关键线索 → 对抗/抉择 → 结局
```

每个阶段写清：玩家在哪里、能找到什么、可能遇到什么、离开时带走什么。
大纲确认后再逐场景补写，避免写完一大段才发现方向不对。

## 3. 逐场景写作

每个场景至少包含：

- 入口：玩家为什么来、怎么进来。
- 可发现内容：线索、物品、NPC、秘密通道。
- 风险：战斗、陷阱、环境、社交冲突。
- 出口：离开时能带走的信息、物品、新地点或盟友。

场景之间用普通连通、隐藏通道或单向离开连接；需要条件才能进的地方要确保条件真的能满足。

## 4. 线索冗余

任何推进主线的关键结论，至少给三种获取方式：

1. 现场观察（不用检定或低难度检定）。
2. NPC / 文献 / 档案。
3. 检定或代价（消耗资源、冒风险、牺牲某物）。

检定失败时给“更模糊但还能继续”的信息，不要让队伍卡死。

## 5. NPC 与阵营

每个重要 NPC 写清：目标、动机、知道的信息、常驻位置、与其他 NPC 的关系、
态度与可被说服/激怒的触发点。NPC 不要只是发任务的工具人。

## 6. 冲突与替代方案

不是所有冲突都要靠战斗解决。至少为关键冲突准备两种替代方案：
谈判、潜行、逃跑、破坏环境、利用线索、消耗物品、拉拢第三方。

## 7. 结局条件

至少两个结局，每个都要有明确条件；结局节点要能从起点走到。
条件只使用结构化原子（线索、物品、旗标、访问、检定、时钟或组合），
不要把自然语言条件写进 completion。

## 8. 导入前自检

- 每个场景都有正文与摘要。
- 关键地点、NPC、线索、结局都在图谱里，且从起点可达。
- 触发器引用的地点/NPC/线索 id 都存在。
- 没有把其它规则集的概念、数值或职业体系混进来。
- 剧本包显式声明 ruleset_id，并说明使用的规则集。
- 先调用导入工具生成待确认预览，用户确认后再创建。
