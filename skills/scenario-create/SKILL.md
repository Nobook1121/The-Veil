# CoC 7e 剧本创作 Skill（The Veil Scenario Create）

## 先确认：你在创作什么

**你正在和用户一起创作一个 CoC 7e（克苏鲁的呼唤第七版）剧本，不是 DND，也不是小说。**

- 玩家扮演**调查员**，不是英雄；核心体验是调查、推理、冒险与面对不可名状之物。
- 规则语言使用 CoC 7e：技能检定（常规/困难/极难）、理智（Sanity）、幸运、战斗轮、伤害加成、护甲、疯狂。
- 不要出现 DND 的等级、职业法术位、AC、d20 检定、经验值等概念。
- 剧本最终要能被《帷幕》网站导入、建图、开房间游玩。

本 Skill 产出的是一个 JSON 文件：`<剧本名>.veil-scenario.json`。  
它包含剧本信息、模块正文、世界书关键词、世界树图谱、触发器、战斗数据与结局条件。

---

## 协作原则（必须遵守）

1. **一次只问一组问题**，不要一口气抛出十个问题。
2. **先大纲、后正文**：用户确认大纲前，不要写完整场景。
3. **不替用户做关键决定**：主题、时代、调查员动机、结局走向至少给出 2–3 个选项。
4. **只写用户确认过的设定**；缺信息时留白或给选项，不要臆造。
5. **每个阶段结束都给用户一个可检查的中间产物**（一页大纲、房间清单、线索表、触发器表）。
6. 创作内容涉及血腥、恐怖、精神疾病等题材时，先与用户确认内容红线。

## 工作流程

### 阶段 0：创作简报（先问清楚）

向用户确认以下信息（可分批提问）：

| 项目 | 说明 |
| --- | --- |
| 调查主题 | 失踪案、古宅、邪教仪式、都市怪谈、荒野异象…… |
| 时代与地点 | 默认 1920 年代美国；也可现代、民国、维多利亚等 |
| 玩家人数 | 1–4 人，影响线索密度与战斗强度 |
| 调查员入场方式 | 受雇、收到信件、偶遇、共同友人失踪 |
| 基调 | 调查为主 / 恐怖压迫 / 少量战斗 / 战斗较多 |
| 预计时长 | 1 次、2–3 次、长篇 |
| 结局数量 | 至少 2 个（成功、失败/牺牲、逃脱/疯狂等） |
| 内容红线 | 是否接受血腥、儿童受害、精神疾病、自杀等 |

把答案整理成一份 **创作简报** 给用户确认。

### 阶段 1：一页大纲（必须等用户确认）

按 CoC 的经典调查结构写：

```
钩子（为什么调查） → 初步调查（1 个入口房间） → 深入调查（2–4 个房间/线索链）
→ 真相与对抗（仪式/怪物/NPC 摊牌） → 结局（成功 / 失败 / 逃脱等分支）
```

同时给出：

- 一句话梗概
- 3–5 个关键场景（房间）及其作用
- 核心真相（KP 知道、玩家要查出来的事）
- 至少 3 条线索链（每条都要有备用获取方式）
- 2–4 个 NPC 及其动机
- 结局清单与达成条件

用户确认后再进入正文。

### 阶段 2：场景与线索

为每个房间写：

- `id`（英文/拼音，稳定唯一，直接作为图谱地点 id）
- `title`、`summary`（30–120 字客观摘要）、`content`（KP 可读正文）
- 可见性：玩家可感知 = `public`；真相/秘密 = `kp_only`；需条件揭示 = `hidden`
- 该房间出现的 **NPC、可获取物品、关键线索** 清单

线索设计遵守「三重原则」：**同一个关键结论至少有 3 条不同途径**（现场观察、NPC 对话、文献/物品、检定成功）。不要把剧情推进押在单次检定上。

### 阶段 3：NPC、怪物与战斗

每个 NPC 写清：

- 姓名、身份、动机、对调查员的态度
- 他知道什么（`knows` 线索）
- 他常驻哪里（`inhabits` 地点）
- 与其他 NPC 的关系（`relationship`，label 写父子/敌对/雇佣/主从等）
- 是否可能进入战斗；若可能，给出 CoC 7e 战斗数值

战斗数值至少包含：`STR`、`CON`、`SIZ`、`DEX`、`HP`、`DB`（伤害加成）、`build`、`MOV`、`armor`，以及武器/技能。低强度杂兵建议 HP 6–10、无护甲；首领 HP 12–18、护甲 0–3。

战斗不是默认解法：先给谈判、潜行、逃跑、环境利用等替代方案。

### 阶段 4：触发器（可选但推荐）

触发器是「玩家到达/发现/对话时自动推给玩家的内容」，可以放：

- 进入房间时的场景描写
- 发现线索时的 handout（信件、日记、剪报）
- NPC 对话片段
- 手动触发的仪式/战斗提示

**富文本触发器**用 `attachments` 里的 `richtext`，`body` 用 Markdown：
标题、粗体、列表、引用、表格图片链接都可以。不要依赖外部图片。

触发器必须绑定到真实存在的地点/NPC/线索/时钟；引用不存在的 id 会在校验时报错。

### 阶段 5：结局

至少 2 个结局节点，每个都要有 `completion` 条件，例如：

```json
{"all": [{"clue": "ritual_diagram"}, {"item": "silver_dagger"}]}
{"any": [{"visited": "cellar"}, {"check": {"skill": "侦查", "result": "success"}}]}
{"clock": "doom_clock", "gte": 4}
```

结局必须是可达的：从起点沿 `adjacent / portal / next / leads_to` 能走到。  
允许开放式收尾时，在结局模块写 `open_ending: true`。

### 阶段 6：组装剧本包

按 `references/bundle-schema.md` 输出完整 JSON。重点检查：

1. 每个 `scene` / `ending` 模块都有同 id 的图谱节点。
2. 所有 NPC、物品、线索都有节点，并用 `inhabits` / `contains` / `knows` 写明归属。
3. 所有边的 `from` / `to` 都真实存在。
4. `relationship` 只连接两个 NPC。
5. 触发器 `binding` 引用的地点/NPC/线索/时钟都真实存在。
6. 每个结局都有 `completion`，且结局可达。
7. 至少一个场景包含战斗数值（若剧本有战斗）。

### 阶段 7：校验并交付

把 JSON 保存为 `剧本名.veil-scenario.json`，运行：

```bash
python scripts/validate_bundle.py 剧本名.veil-scenario.json --fix -o 剧本名.fixed.json
```

- `ERROR` 必须修完；`WARN` 要逐条解释。
- 把 `剧本名.fixed.json` 交给用户导入网站。
- 同时交付：创作简报、房间清单、线索表、触发器表、NPC/战斗表、结局条件、未解决问题。

## 导入网站

网站「剧本」页 → 导入 → 选择 `.veil-scenario.json`。导入后先看预览：

- 剔除项（创作剧本通常为空）
- 模块数、节点/边数
- 触发器数量与结局数量
- 校验警告与修复项

确认后发布，图谱会写入世界树，就可以开房间游玩。

站内 Agent 不需要先产出文件：调用 `scenarios.create_guide` 读取本 Skill，再调用
`scenarios.import_script` 传入 `bundle` 生成待确认预览，用户确认后创建。

---

## 严格输出约定

- 只输出合法 JSON，不要包在 Markdown 代码块里，不要加注释。
- 不编造用户没确认的剧情；不确定就省略或提问。
- 每阶段先给用户看该阶段产物，再进入下一阶段。
- 剧本正文用中文；id 用英文/拼音；关键词放专名，不要放「调查」「房间」这类通用词。

详细资料见：

- `references/coc7-authoring.md`：CoC 7e 创作规范、线索与战斗设计
- `references/bundle-schema.md`：剧本包字段与触发器/战斗/结局写法
- `references/prompts.md`：与用户协作的分阶段提示词
- `scripts/validate_bundle.py`：导入前自检脚本
