# 外链 BGM 曲源调研与配置说明

> 调研日期：2026-11-07 · 范围：只做调研，不改代码、不提交
> 目标：找国内可直连、配置方便、授权明确的外链 BGM 曲源；并把现有 Jamendo / Openverse 的配置写清楚。

---

## 0. 先说结论

**推荐排序（按"能自动接入 + 授权干净 + 可播放"三条硬指标）**

| 排名 | 曲源 | 角色 | 一句话理由 |
|---|---|---|---|
| 1 | **Jamendo** | 主源 | 唯一同时具备"公开 API + 按标签检索 + 每曲 CC 许可字段 + 稳定音频直链"的源；需要 Client ID，申请免费 |
| 2 | **Openverse** | 次源 / 兜底 | 零配置、无需 Key、一接口聚合多家 CC 源；但**本次复测 API 连续连接超时**，不能当唯一源 |
| 3 | **ccMixter** | 可选第三源 | 有公开 Query API、无需 Key、返回 `download_url` 直链；但许可证混有 NC，必须在服务端过滤 |
| 4 | **Wikimedia Commons** | 兜底补位 | API 与音频直链都带 `Access-Control-Allow-Origin: *`；但格式是 ogg/flac、没有情绪/氛围标签，检索质量差 |
| — | Internet Archive | 不推荐 | 可用但慢（4–10s，文件 8–15s），授权字段覆盖率低 |
| — | Pixabay Music | 不能自动接入 | **官方 API 只有图片和视频，没有音乐端点**；站点受 Cloudflare 防护且禁止抓取 |
| — | Free Music Archive | 不能自动接入 | 站点可访问，但**没有公开 API**（`api.freemusicarchive.org` TLS 失败），只能抓页面 |
| — | Freesound | 定位不符 | 需 token，且是**音效库**不是配乐库；更适合将来的环境音采样 |
| — | Musopen | 不可用 | 本机被 Cloudflare 403 拦截；且以 CC BY-NC 古典乐为主 |
| — | 淘声网 / 爱给网 / 耳聆网 | 不能上线 | 均无可用的公开 API，授权多为"免费下载但限制商用/需授权书"，与 CC 白名单不兼容 |

**最重要的一条架构结论**：本项目**不需要上游给 CORS 头**。检索在服务端（`requests`），音频走同源代理 `/api/immersive/rooms/<room_id>/music/external/audio/<track_key>`，浏览器只与自己的域名通信。因此"有没有 `Access-Control-Allow-Origin`"只影响"将来是否改成浏览器直连"，**不影响现在能否进 Web Audio**。真正要看的只有：服务端能否取到、直链是否稳定、授权是否允许第三方使用。

## 3. 逐个核实

### 3.1 Jamendo（推荐主源）

- **域名 / 端点**：`https://api.jamendo.com/v3.0/tracks/`；音频 CDN 实测为 `prod-1.storage.jamendo.com`（OVH，法国）；API 本身在 Cloudflare 后（DNS 实测 104.26.x / 172.67.x）。
- **Key 与申请**：需要 `client_id`。开发者门户 <https://devportal.jamendo.com/> 注册后创建应用即可获得，免费。
- **额度【文档】**：官方首页的 API 套餐表写的是 Non-Commercial Apps「Up to 35,000 requests per month」，Commercial Apps「Unlimited」。也就是说**免费额度对应非商业应用**；若你的部署用于收费服务，需要走他们的商业套餐。本项目是自托管、Apache-2.0 开源，按非商业用途申请即可，但这条边界要写进部署文档。
- **授权**：逐曲 CC，接口通过 `include=licenses+musicinfo` 返回 `license_ccurl`。代码里只放行 `cc0 / by / by-sa`（`music_external_license_allow`），并按曲目字段生成署名。
- **CORS【实测】**：API 带 `Access-Control-Allow-Origin: *`；音频 CDN **不带** ACAO。但见第 4 节——我们走服务端代理，不受影响。
- **国内可达性**：API 在 Cloudflare 后，国内一般可访问但时延受运营商与 Cloudflare 线路影响；**音频 CDN 在法国 OVH，不在 Cloudflare 上**，这是国内播放的主要不确定点（首包慢）。建议开 `music_external_cache_audio = true` 让服务端缓存音频本体，避免每次重新跨境拉流。
- **结论**：主源。理由是唯一同时满足"标签检索 + 逐曲许可字段 + 稳定直链"的源。

### 3.2 Openverse（推荐次源，但今天不可靠）

- **域名 / 端点**：`https://api.openverse.org/v1/audio/`。DNS 实测解析到 `198.44.185.131`（香港，VpsQuan）。
- **Key**：**不需要**。匿名调用直接返回 200（实测 3 次）。官方文档另有「Authentication and Throttling」章节（有节流，注册 client 可提高额度）；**该页本次未能取到原文（连接超时），具体数字未核实，不在此编造**。
- **授权**：按 `license=cc0,by,by-sa` 过滤，返回 `license`、`license_url`、`attribution`、`foreign_landing_url`，足够满足署名要求。
- **CORS【实测】**：带 `Origin` 的 GET 返回 `Access-Control-Allow-Origin: *`，`OPTIONS` 预检也是 `*`。
- **可用性【本次最重要的一条实测】**：
  - 第一轮探测：3 次 200，2.83s / 2.91s / 3.13s；
  - 同一台机器间隔数分钟后复测：**连续 connect timeout**（16s、40s 级），而同期 Jamendo(2.5s)、ccMixter(6.3s)、Wikimedia(3.4s)、Archive(4.4s)、Freesound(2.6s) 全部正常。
  - 说明：不是本机断网，是**这条到 Openverse 的链路本身不稳定**。
- **关键陷阱**：Openverse 只聚合元数据，**`url` 字段指向原始托管方**。实测返回的音频是 `prod-1.storage.jamendo.com` 的 mp3。所以"Openverse 能连" ≠ "Openverse 返回的音频能播"，上游挂了一样播不了。
- **结论**：次源可以，但**绝不能当唯一源**；必须保留 Jamendo 或程序化底床兜底。现有代码的 `external → procedural → hold` 降级链正好适配。

### 3.3 ccMixter（可作第三源）

- **端点**：`https://ccmixter.org/api/query?f=json&tags=ambient&lic=by`。
- **Key**：不需要。
- **授权**：**逐曲不同**。实测同一批结果里同时出现 `Attribution`（`creativecommons.org/licenses/by/2.5/`）和 `Noncommercial Sampling Plus`（`licenses/nc-sampling+/1.0/`）。即使加了 `lic=by` 参数，仍应在服务端用 `license_url` 再判一次白名单。
- **注意不要混淆**：ccMixter 站点页脚写的是"This text and images on this site are licensed under CC BY-NC 4.0"——那是**站点文字与图片**的许可，不是曲目许可。曲目看每条的 `license_url`。
- **直链【实测】**：`files[]` 里每条包含 `download_url`，形如 `https://ccmixter.org/content/<user>/<file>.mp3`。
- **CORS**：无 ACAO（响应 `text/plain`），服务端取没问题。
- **时延【实测】**：5.5–6.3s，明显慢于 Jamendo。适合低频补充，不适合主检索。
- **结论**：可以作为第三源接入，前提是许可证二次过滤。

### 3.4 Wikimedia Commons（兜底）

- **端点**：`https://commons.wikimedia.org/w/api.php`（`action=query` + `generator=search` + `prop=imageinfo&iiprop=url|extmetadata`）。
- **授权**：`extmetadata.LicenseShortName` 可读到 `CC0`、`CC BY 3.0`、`CC BY-SA` 等。
- **CORS【实测】**：API 与音频直链**都返回 `Access-Control-Allow-Origin: *`**，是这批源里 CORS 最友好的。
- **实测样例**：`Alex-Productions - Deep (Dark Ambient).oga`（CC BY 3.0，2.2MB，`application/ogg`）、`Ambient music test, Yamaha CK61.flac`（CC0，10MB，`audio/x-flac`）。
- **硬伤**：格式是 **ogg / flac**，Safari 对 ogg 支持有限（`<audio>` 直接播 ogg-vorbis 在 iOS Safari 上会失败）；而且没有统一的情绪/氛围标签，只能全文检索，命中率低。
- **结论**：只在"明确知道要哪首"时用，不适合做常规自动配乐。

### 3.5 Internet Archive（不推荐）

- **端点**：`https://archive.org/advancedsearch.php`、`https://archive.org/metadata/<identifier>`。
- **实测**：搜索 200 / 4.4–10s，音频文件 HEAD 8–15s；CORS 为 `*`。
- **授权问题**：馆藏以"上传者声明"为主，`licenseurl` 覆盖率低且写法不统一。我用 `licenseurl:"*creativecommons.org/licenses/by/*"` 过滤时 `numFound = 0`——说明这个字段要么大量缺失，要么查询语法不可靠。这意味着**无法在入库时保证授权干净**。
- **结论**：技术上能接，但慢 + 授权不可控，不建议进白名单。

### 3.6 Pixabay Music（看着最合适，实际不能上）

这是最容易被误判的一个，单独说明：

- **官方 API 文档原文【实测 200】**："Our API is a RESTful interface for searching and retrieving **royalty-free images and videos** released by Pixabay." 文档目录只有 Rate limit / Hotlinking / Error handling / Search images / Search videos。**没有音乐端点，`/api/` 不接受音频检索**。
- 音乐页 `https://pixabay.com/music/` 与本机请求均被 **Cloudflare 挑战页（403，`Just a moment...`）** 拦截。
- 也就是说：想用它，只能**抓页面**。而抓取既不稳定（随时被 CF 拦），又违反站点条款里"未经书面许可不得使用爬虫/抓取器"的限制。
- 授权本身：Pixabay Content License 允许免费商用、通常不要求署名，但**禁止原样再分发、禁止做成竞争性服务**；用于游戏内 BGM 播放属于"创作性使用"，边界上是可以的，但前提是合法取得内容——而合法取得的路径（API）不存在。
- **结论：不能自动接入。** 若确实要用，只能人工在站内挑选、逐首核对、本地打包，且要接受"内容随时可能被下架"的风险。

### 3.7 Free Music Archive（不能自动接入）

- **站点可达【实测】**：`freemusicarchive.org` 200 / 2.6–5.1s，风格页 `/genre/Ambient/` 也返回 200。
- **没有 API【实测】**：`api.freemusicarchive.org` 直接 TLS 失败，站点 `/api/` 404。FMA 的旧 API 已下线，现在只面向人工浏览。
- **授权**：逐曲 CC，且**混有 NC 与 ND**，必须逐首判断，不能按站点整体授权。
- **结论**：除非做网页抓取（有条款与稳定性双重风险），否则不能作为自动源。

### 3.8 Freesound（不是 BGM 源）

- **端点**：`https://freesound.org/apiv2/search/text/`，需要 token（未带 token 实测 **401**）。
- **定位**：音效（环境声、拟音），音乐曲目很少；许可证含 cc0 / by / by-nc。
- **结论**：BGM 场景不用；将来若要把程序化环境音替换成真实采样，它是更合适的候选（且我们已有 `ambient-engine.ts` 的场景/事件接口，替换成本低）。

### 3.9 Musopen

- **实测**：`https://musopen.org/` 403（Cloudflare 挑战）。
- 以古典乐为主，下载通常需要账号，授权多为 CC BY-NC。
- **结论**：不可用。

### 3.10 国内素材站：淘声网 / 爱给网 / 耳聆网

这三个是用户最可能想到的"国内直连"答案，必须把话说清楚：

- **DNS 在国内【实测】**：
  - `www.tosound.com` → `120.77.239.22`（广东，阿里云）
  - `www.aigei.com` → `139.129.112.11`（山东，阿里云）
  - `www.ear0.com` → `116.211.128.118`（湖北电信）、`27.155.113.116`（福建）
  都是国内节点，国内访问**理论上很快**。
- **本机访问【实测】**：HTTPS 全部 `SSLEOFError`（TLS 握手被中途断开），HTTP 返回 **503**。这是"境外 IP 被拒"的典型特征，**不能据此判定国内不可达**——反过来也说明我无法在这里替你验证国内速度。
- **没有公开 API**：这三家都没有面向第三方应用的检索接口文档，只能抓页面或让用户手动下载。
- **授权是硬伤**：这类站的"免费"通常指"站内免费下载"，条款普遍限制**商业使用、二次分发、影视/游戏内嵌**，部分要求**单独申请授权书**或强制署名+来源标注。这与本项目"只播 cc0 / by / by-sa，且能在界面显示可点击署名"的白名单模型不兼容。
- **结论**：**不能作为合规自动源接入**。如果你有某家的书面商用授权，那就属于"自有授权曲库"，应当作为独立 provider 单独实现（带授权凭证字段），而不是塞进 CC 白名单。

## 4. 为什么 CORS 在这套架构里不是决定项

看代码就能确认：

- 检索：`backend/trpg_server/immersive/external_music/providers.py` 用服务端 `requests` 直接请求上游 API。
- 播放：浏览器请求的是同源地址 `GET /api/immersive/rooms/<room_id>/music/external/audio/<track_key>`（`backend/trpg_server/routes/immersive.py:460`），由服务端校验登录与房间权限后再去拉上游音频，透传 `Range`。

因此：

1. 上游 API 不给 CORS，不影响检索；
2. 上游音频不给 CORS，不影响 `<audio>` 播放；
3. 反过来，**如果将来改成浏览器直连上游**，才必须要求 ACAO，而且会同时引入混合内容、防盗链、追踪等问题。

真正会卡住接入的是：**上游是否允许服务端抓取**（条款）、**直链是否长期稳定**（签名过期、防盗链）、**授权是否允许第三方应用嵌入播放**。

## 5. 现有两个源怎么配（可执行步骤）

### 5.1 Jamendo：申请并填入 Client ID

**第一步，申请**

1. 打开开发者门户 <https://devportal.jamendo.com/>，注册/登录；
2. 创建应用（Application），用途选只读即可；
3. 复制生成的 **Client ID**（是一串十六进制，不是 secret）。

**第二步，填到配置里（三选一，优先级从高到低）**

| 方式 | 位置 | 说明 |
|---|---|---|
| 管理界面 | 设置 → 实时沉浸 → 外链曲库 → `Jamendo client_id` | 输入后保存即生效；**该输入框不回显已保存的值**，留空保存不会清空旧值 |
| 配置文件 | `config/general.toml` → `[immersive]` → `music_external_jamendo_client_id = "你的ID"` | 适合首次部署批量写入 |
| 环境变量 | `TRPG_JAMENDO_CLIENT_ID=你的ID` | 适合容器/密钥管理；容器里优先用它 |

代码里的取值顺序是"配置项优先，其次环境变量"（`providers.py` 的 `jamendo_client_id()`）。两者都空时，Jamendo 会返回 `missing_credentials` 并自动降级到 Openverse / 程序化底床，不会报错。

**第三步，打开引擎**

设置 → 实时沉浸 → 音乐 → **音乐引擎** 选 `external`，保存。对应配置：

```toml
[immersive]
music_engine = "procedural"   # 改成 "external"
music_external_providers = "jamendo,openverse"
music_external_license_allow = "cc0,by,by-sa"
music_external_instrumental_only = true
music_external_jamendo_client_id = "你的ID"
```

> 房间侧只能**降级**不能升级：站点是 `procedural` 时，房间选 `external` 会被服务端拒绝并回落（原因 `room_cannot_upgrade`）。

### 5.2 Openverse：零配置，但要接受它的不稳定

- **不需要 Key，不需要注册**。只要 `music_external_providers` 里包含 `openverse`，就会作为次源参与检索。
- **调用限制**：官方文档有独立的「Authentication and Throttling」章节（匿名有节流，注册 client 可提高额度）。本次该页未能取到原文，**具体阈值未核实**，部署前建议人工打开 <https://docs.openverse.org/> 确认一次。
- **实际风险**：本次复测出现连续连接超时；且返回的音频直链指向上游（实测多为 Jamendo CDN）。建议：
  - 保留 Jamendo 在主位；
  - 保持 `music_external_circuit_failures = 3` / `music_external_circuit_cooldown_s = 600` 的熔断默认值，避免每回合都等超时；
  - 不要调大 `music_external_timeout`（默认 6s）。

### 5.3 怎么验证配置生效

**方式 A：房间控制台（最直接）**

```text
immersive music show
```
看当前解析出的引擎与原因（`external` / `procedural` / `off`，以及 `room_cannot_upgrade`、`circuit_open`、`throttled` 等）。

```text
immersive music search 雨夜街道 --tags=dark,ambient
```
- 成功：打印「已重新检索并切曲：曲名 — 作者」+ 许可 + 署名 + 来源 + 备选数量；
- 失败：打印「外链检索未命中（reason），已降级到程序化底床」，`reason` 会告诉你到底是 `missing_credentials`、`network_error`、`empty` 还是熔断。

**方式 B：HTTP 接口**

```text
POST /api/immersive/rooms/<room_id>/music/external/search
Content-Type: application/json

{"scene": "雨夜街道", "tags": ["dark", "ambient"], "profile": "suspense", "intensity": "medium", "force": true}
```
需要登录且具备该房间访问权限。返回 `status: selected` 表示检索成功；否则返回 409 与 `reason`。

**方式 C：浏览器控制台**

```js
window.TrpgImmersiveExternal.state()
```
可看到当前外链播放器状态与最近一次降级原因。

**方式 D：只看配置有没有落盘**

```text
type config\general.toml | findstr /C:"music_external_jamendo_client_id" /C:"music_engine"
```

### 5.4 配置项速查

| 配置项 | 默认 | 作用 |
|---|---|---|
| `music_engine` | `procedural` | `procedural` / `external` / `off` |
| `music_engine_allowed` | `procedural,external` | 管理员允许的档位集合，房间只能取其中更低的一档 |
| `music_external_providers` | `jamendo,openverse` | 参与检索的源，按顺序尝试 |

| `music_external_instrumental_only` | `true` | 只接受器乐，避免歌词盖住 KP 旁白 |

## 6. 授权存疑、不能直接上的源（单独标出）

| 源 | 为什么不能直接上 |
|---|---|
| **淘声网 / 爱给网 / 耳聆网** | ①没有公开 API，只能抓页面；②"免费下载"≠"允许第三方应用内嵌播放"，条款普遍限制商用、二次分发、影视游戏内嵌，部分要求单独授权书；③本机实测 TLS/503，国内速度无法在此验证。**除非拿到书面商用授权，否则不要接。** |
| **Pixabay Music** | ①官方 API **不含音乐端点**（文档原文只有 images and videos）；②站点 Cloudflare 防护 + 条款禁止抓取；③即使授权允许创作性使用，也没有合法稳定的获取通道。 |
| **Free Music Archive** | ①公开 API 已下线（`api.freemusicarchive.org` TLS 失败）；②曲目混有 NC/ND，必须逐首判断。 |
| **网易云音乐外链播放器** | 上一轮已单独分析：绕过会员/地域限制、聚合链接、VIP 试听片段等均构成高法律风险（参考 (2023)浙民终1090号判决，判赔 80 万元），技术上也不可控（播放器会切歌、可能只给 30s 试听）。**不要接。** |
| **Internet Archive** | 技术上可接，但授权字段缺失严重，无法保证"每首都干净"，不适合进白名单。 |

## 7. 如果你要"国内直连、配置方便"

需要接受一个现实：**同时满足"国内直连 + 合法 CC 授权 + 有公开 API + 能自动检索"这四个条件的源，目前没有。**

可行的组合策略（按代价从低到高）：

1. **现状最优**：Jamendo（主）+ Openverse（次）+ 程序化底床兜底。国内要做的是**在部署机实测一次**（第 8 节命令），并考虑开启 `music_external_cache_audio`。
2. **加第三源**：接 ccMixter，补足 Openverse 不稳定时的候选量。改动量小（新增一个 provider 适配器 + 许可证过滤），但会引入每次 5–6s 的检索延迟，建议只在主源空结果时触发。
3. **自建曲库（最稳）**：人工从 Jamendo / Pixabay / incompetech 挑选并下载一批 CC 曲目，走现有的 `bgm_library`（本地曲库）而不是外链。缺点是失去"按剧情自动换曲"的能力，优点是零跨境依赖、零授权风险、可离线。
4. **国内素材站**：只有拿到书面商用授权后才考虑，且要按"自有授权曲库"接入，不能混进 CC 白名单。

## 8. 国内实测命令（请在你的机器上跑一次）

下面命令用于在**中国大陆网络**下验证可达性与时延。Windows PowerShell：

```powershell
# 1) 出口 IP 与归属（确认你确实在国内网络）
curl.exe -s https://ipinfo.io/json

# 2) Jamendo API（把 CLIENT_ID 换成你的）
curl.exe -s -o NUL -w "jamendo api: %{http_code} %{time_total}s`n" "https://api.jamendo.com/v3.0/tracks/?client_id=CLIENT_ID&format=json&limit=1"

# 3) Jamendo 音频 CDN（跨境拉流的关键指标）
curl.exe -s -o NUL -w "jamendo cdn: %{http_code} %{time_total}s`n" "https://prod-1.storage.jamendo.com/?trackid=1&format=mp32"

# 4) Openverse
curl.exe -s -o NUL -w "openverse: %{http_code} %{time_total}s`n" "https://api.openverse.org/v1/audio/?q=ambient&page_size=1"

# 5) ccMixter
curl.exe -s -o NUL -w "ccmixter: %{http_code} %{time_total}s`n" "https://ccmixter.org/api/query?f=json&tags=ambient&limit=1"

# 6) 国内站（看是否真的比境外快）
curl.exe -s -o NUL -w "tosound: %{http_code} %{time_total}s`n" "https://www.tosound.com/"
curl.exe -s -o NUL -w "aigei:  %{http_code} %{time_total}s`n" "https://www.aigei.com/music/"
```

判读方式：

- `000` 或长时间无响应 = 不可达（要代理）；
- `2xx` 且 `time_total` < 1s = 国内直连良好；
- `2xx` 但 `time_total` > 3s = 能连但慢，建议开音频缓存；
- Jamendo 特别注意第 3 条：**API 通不代表音频 CDN 通**，音频在法国 OVH。
