## 0. 结论先行

现状的问题不是「噪声选得不好」，而是**四件事同时缺位**：没有 1/f 频谱斜率、没有共振峰、没有可听的颗粒密度、没有任何一层在慢速移动。再叠加一个致命细节：**2 秒白噪单声道 buffer 直接 loop，且主链 8.5 kHz 低通**，出来的就是一段被削掉低频和空气感、以 2 秒为周期重复的宽带嘶声——这正是雪花噪声的配方。

重制方案分四步，前两步就能解决 80% 的听感问题：

1. **换噪声源**：白噪 → 粉噪/棕噪双声道、16 s 交叉淡化无缝循环，多副本错相位叠加；
2. **换主链**：90 Hz 高通 → 28 Hz；8.5 kHz 低通改为场景化的 `high shelf` + 仅在配乐播放时动态收窄；
3. **换配方**：每场景 3–5 层「底层 + 体感层 + 颗粒层 + 空气层」，滤波链从单个 biquad 改成 2–3 级串联 + `peaking` 共振峰；
4. **换调制**：正弦 LFO 调音量 → 滤波器频率的随机游走（8–20 s 换目标）+ 泊松事件 + 三时间尺度强度演化。

采样只在两处必要：**人声嘈杂（babble）** 与 **真实车流经过**。其余 16 个场景全部程序化可达到可用水准。采样总量预算 **≤ 2.5 MB（硬上限 6 MB）**，opus 优先。打包脚本目前把 `data/assets/bgm` 列为**禁止内容并断言不存在**，内置素材必须放独立目录 `data/assets/ambient`，同时改 `$runtimeDirs` / `$required`，并在 `THIRD-PARTY-LICENSES.md` 增加一节逐文件登记。

公开 API（`apply / stop / setEnabled / isEnabled / setVolume / getVolume / isRunning / getScene / resume / setMusicActive / diagnostics`）**不需要改签名**，`plan.intensity` 已经够用。改动集中在一个模块内部，风险可控。

## 1. 现状诊断（代码事实）

### 1.1 噪声源

`music-engine.ts` 的 `createNoiseBuffer`：

```ts
for (...) data[index] = Math.random() * 2 - 1;   // 纯白噪，单声道
```

- 只有白噪（PSD 平坦，0 dB/oct），**没有粉噪/棕噪**；
- buffer 时长 2 s，`loop = true`，`playbackRate` 仅在 `0.9–1.1` 随机一次——循环周期被钉死在约 1.8–2.2 s；
- 单声道 buffer + `StereoPannerNode`：左右声道内容完全相同，只做电平差，**没有双耳去相关**，听感「贴在脑袋中间」。

### 1.2 主链

[ambient-engine.ts](file:///c:/Mine/AIbased%20TRPG/frontend/src/app/immersive/ambient-engine.ts#L294-L323)：

```
masterGain → highpass 90Hz → peaking 1100Hz Q0.9 -3.5dB → lowpass 8500Hz → mixInput
```

- 90 Hz 高通把雷的 30–80 Hz 次低频整段切掉；
- 8.5 kHz 低通把雨的「沙沙空气感」（4.4–5.6 kHz 以上的颗粒泛音）削平；
- 剩下的就是 200 Hz–8 kHz 的平直噪声，正是电视雪花频段。

### 1.3 分层与调制

每个场景 2–3 层，每层：

- **一个** biquad（`lowpass/bandpass/highpass`），Q 默认 0.7；
- 音量 = 固定值 + 一个正弦 LFO 在 `level.gain` 上叠加（`rate 0.025–0.12 Hz`）；
- **滤波器频率从不变化** → 频谱恒定，这是「一成不变」的主因；
- 低画质档位直接砍层（`quality>=1` 只留 2 层，`>=2` 只留 1 层且无事件）。

### 1.4 事件

事件间隔用 `min + rand*(max-min)`，雨滴 `1.4–3.8 s` 一颗、增益 0.04；`spawnDrop` 是 1 个带通噪声 + 20–160 ms 指数衰减。结果是**每秒不到 1 颗、几乎听不见的雨滴**，主体只剩噪声床。

### 1.5 换场

2.2 s 等功率交叉淡化，正确；但**同场景重复 `apply()` 直接 return**（`currentScene === scene`），所以同一场景内永远不会重新随机化——这是「一直不变」的第二层原因。

> 结论：不是参数没调好，而是缺少**频谱斜率、共振峰、颗粒密度、时变调制、双声道去相关**这五个结构性要素。

## 2. 合成基础：先把「雪花噪声」翻译成频谱问题

### 2.1 三种噪声色及其用途

| 噪声 | 频谱斜率 | 听感 | 在本项目里的正确用途 |
| --- | --- | --- | --- |
| 白噪 white | 0 dB/oct，能量均匀 | 「嘶——」，电视雪花 | **只做瞬态源**（雨滴、爆裂、树叶摩擦的 0.5 ms 激励），或经 4 kHz 以上高通做「空气层」；**不能直接当雨/风床** |
| 粉噪 pink | −3 dB/oct（每倍频程 −3 dB） | 自然、宽带、像瀑布/雨 | 雨的主体、溪流、树叶底噪、室内空气感 |
| 棕噪 brown | −6 dB/oct（每倍频程 −6 dB） | 低沉、厚、像远处交通/风 | 风的主体、雷、车流底盘、房间底噪、次低频 |

判定标准很直接：**当前雨声之所以像雪花，是因为它的频谱是平的（白噪）且被低通截到 8.5 kHz**。真实的雨在 600–1200 Hz 有显著能量、在 4.4–5.6 kHz 也有显著成分，整体呈下降趋势，并叠加大量的随机瞬态与气泡共振（[Bedoya 等，2018](https://arxiv.org/html/1804.05502v1)；[雨落在水面 200–800 Hz 气泡共振](https://insomnus.app/blog/frequency-spectrum-natural-sounds/)）。

| 声音 | 关键频段 | 出处 |
| --- | --- | --- |

### 2.3 常用的频谱整形手法（Web Audio 可直写）

1. **级联低通/高通**：`BiquadFilterNode` 是 12 dB/oct，两级 = 24 dB/oct，用于模拟真实的滚降（真实自然声多为 12 dB/oct 缓降，见 [有机音效合成](https://www.audioscene.org/article/designing-organic-sound-effects-with-synthesized-elements/)）。
2. **共振峰（formant）**：`peaking` + `Q 3–12` + `gain +4~+10 dB`，用来做雨滴的「啪」、水滴的「咚」、雷的 200 Hz 鼓包、风的「呜」。
3. **搁架（shelf）**：`highshelf` 做空气感，`lowshelf` 做厚度；比整体低通自然。
4. **动态滤波**：把 `filter.frequency` 作为调制目标，比调音量更能制造「风在动」的错觉。
5. **颗粒（granular）**：短噪声 burst（5–120 ms）+ 带通 + 指数衰减，是雨滴、爆裂、树叶、脚步的通用原子。

## 3. 分场景配方表

### 3.1 记号约定

- **层电平**：相对场景总线的 dBFS（未加主增益），已按「各层能量占比」配平，层间和约为 −10 ~ −6 dBFS 峰值；
- **滤波链**：JSON 顺序即串联顺序，`BP` = bandpass，`LP` = lowpass，`HP` = highpass，`PK` = peaking，`HS/LS` = 搁架；
- **调制**：`walk` = 随机游走（每 8–20 s 取新目标，`setTargetAtTime` τ=3–8 s），`lfo` = 正弦/三角，`env` = 事件包络；
- **事件速率**：泊松过程 λ（events/s），间隔 `−ln(U)/λ`；
- **强度联动**：`plan.intensity = low/medium/high` → 密度 ×0.55/×1/×1.8，层电平 −4/0/+3 dB，演化速率 ×0.7/×1/×1.4。

#### 暴雨（downpour）

在大雨基础上：

- 雨幕底电平 −13 dB，HP 降到 180 Hz；
- 增加**排水/水流层**：pink → HP 700 Hz → PK 1.8 kHz Q2 +6 dB，电平 −19 dB，缓慢 walk；
- 颗粒云 AM 提升到 40–80 Hz，电平 −19 dB；
- 增加**风耦合层**：brown → LP 320 Hz（随 gust 调制），−24 dB；
- 事件：短促「拍打」λ=2–5，BP 500–1.2 kHz，衰减 80–160 ms，电平 −16 dB。

#### 雷雨（thunderstorm）

暴雨全部层 + 雷事件（见 3.3）。雷的层不并入雨床，走独立总线（见 3.3 的 `thunderBus`），因为需要绕过次低频保护。

#### 滴水（drip，洞穴/室内）

- 主事件：正弦（或高 Q 带通）1.4–3.4 kHz，音高 80–140 ms 内下滑 ×0.55–0.7，衰减 0.18–0.5 s，电平 −16 dB，λ = 0.12–0.6；
- 混响：接一个 1.2–2.0 s 的短卷积（复用 `music-engine` 的 `createReverbBuffer`），湿声 25–35%；
- 底噪：brown LP 160 Hz −34 dB，制造空间感。

| 阵风耦合 | — | gust 事件把上面三层同时 +4~+6 dB | | |

「沙沙」的本质是**大量短颗粒的密度调制**，不是持续噪声。只做噪声层会像瀑布，必须加颗粒。

#### 夜晚虫鸣（insects）

- 蟋蟀声部 3–6 个，每个独立：
  - 载波：正弦 4.8–5.3 kHz（对齐实测基频），频率每 30–90 s 漂移 ±80 Hz；
  - 脉冲：方波/锯齿 AM，25–80 Hz（对齐 80 p/s 量级），占空比 0.25–0.45；
  - 鸣叫包络：0.12–0.4 s 一组，组间静默 0.5–2.5 s，每组内部 2–5 个脉冲串；
  - 声像：固定 ±0.7 内随机，距离感用 LP 8 kHz 模拟；
- 蝉/背景虫：pink → BP 7.5–9 kHz Q8，AM 35–55 Hz，电平 −34 dB，只在「夏夜」变体出现；
- 底噪：brown LP 120 Hz −38 dB + 极低风层。

蟋蟀用**正弦 + AM** 比噪声带通更干净、更像虫；噪声带通适合蝉。

### 3.7 人造环境

#### 车流（traffic）

| 层 | 源 | 滤波链 | 电平 | 调制 |
| --- | --- | --- | --- | --- |
| 车流底盘 | brown | LP 380 Hz Q0.7 → PK 650 Hz Q0.9 +3 dB | −22 dB | 电平 walk ±2 dB / 20–40 s（对应 600–700 Hz 峰值） |
| 胎噪层 | pink | BP 1.2 kHz Q0.6 → HP 800 Hz | −28 dB | walk |
| 远处鸣笛 | 采样/正弦 | 400–900 Hz，短滑音 | −36 dB | λ = 0.02–0.08 |
| 经过车辆 | **采样** | LP 6 kHz，声像 L→R | −13 dB 峰值 | λ = 1/8 ~ 1/25 |

程序化的「经过车辆」可以做出**运动感**（带通中心 500→900→450 Hz + 声像横移），但做不出**发动机的谐波结构**，听感会像「一阵风」。所以车流是建议采样的第二个场景（见 §5）。

#### 说话声/人声嘈杂（crowd）

- **采样为主**（2 个 30 s 循环，随机错位叠加，见 §5）；
- 程序化兜底：
  - 8–12 个「声部」颗粒，每个 0.3–1.2 s；
  - 源 = 脉冲串（基频 90–200 Hz，抖动 ±15%）→ 3 个并联 `peaking` 共振峰（F1 350–800 Hz、F2 900–2400 Hz、F3 2400–3400 Hz，Q 5–8，增益 +8~+12 dB）；
  - 音节包络：2–5 Hz 的随机 AM；
  - 整体再过 LP 3.5 kHz + 短混响，制造「听不清」；
  - 电平 −24 dB，声像散布 ±0.8。
- 说实话：程序化 babble 能做到「像有人在说话」，但做不到「像一群人在说话」；一旦玩家靠近，破绽很明显。因此采样优先级最高。

#### 火堆（fire，已有场景需重做）

| 层 | 源 | 滤波链 | 电平 | 调制 |
| --- | --- | --- | --- | --- |
| 火焰底 | brown | LP 220 Hz Q0.7 | −24 dB | walk ±2 dB |
| 火焰体 | pink | BP 1.4 kHz Q0.6 | −28 dB | walk ±30% |
| 爆裂颗粒 | white 颗粒 | BP 1–6 kHz Q0.9，衰减 5–40 ms | −18 dB | λ = 3–10（暴烈时 15） |
| 低频爆响 | white 颗粒 | LP 160 Hz，衰减 60–180 ms | −22 dB | λ = 0.1–0.4 |

#### 室内底噪（interior / room tone）

- brown → LP 180 Hz，−34 dB（房间的「空气重量」）；
- pink → BP 420 Hz Q1.0，−40 dB，walk（远处活动）；
- 可选 50/100 Hz 电源嗡鸣：正弦 50 Hz + 100 Hz，−46 dB（只在「现代室内」变体）；
- 可选钟表：每 1 s 一次「嗒」，BP 2.6 kHz Q22，衰减 6 ms，双音交替（1.9 kHz / 2.6 kHz），电平 −30 dB。

#### 远处人群（distant-crowd）

- crowd 采样 → LP 1.5 kHz → 短混响 30% → 电平 −28 dB；
- 加 brown LP 200 Hz −34 dB 做「隔墙」感；
- 适合酒馆/集市/城墙外。

#### 留白/压迫（void / dread）

保留现有 drone 思路，但增加 24–30 Hz 次低频（−34 dB）与极慢 walk；不要放颗粒。

### 3.8 场景与关键词映射（需新增）

现有 9 个 `SceneId` 需扩展为 18 个：

## 4. 演化策略：如何彻底消除「一成不变」

分三个时间尺度，互不整除，避免任何周期重合。

### 4.1 事件级（0.1–10 s）：泊松 + 参数随机

- 间隔用 `gap = -ln(1-U)/λ`，**不要**用 `min + rand*(max-min)`（均匀分布会有「规律感」）；
- 每个事件随机化：频率中心（对数均匀）、Q（±20%）、衰减（±30%）、增益（±4 dB）、声像（±0.8）、起始偏移（buffer 内随机位置）；
- 加**簇发**：以 8% 概率触发 2–4 连击（间隔 40–120 ms），模拟真实的雨滴/爆裂成串。

### 4.2 分钟级（8–180 s）：随机游走替代正弦 LFO

- 每层滤波器频率：每 8–20 s 取新目标 `f_new = f_base * 2^(U(-0.45,0.45))`，用 `setTargetAtTime(f_new, now, 3–8)` 平滑过渡；
- 每层电平：每 10–30 s 取目标 ±2 dB，τ=4–10 s；
- 声像：每 20–40 s 漂移 ±0.25；
- 保留 1–2 个正弦 LFO，但**用两个不可公度频率叠加**（如 0.031 Hz + 0.047 Hz），合成周期约 1000 s，远长于单次会话；
- 不建议用 `restart oscillator` 做相位重置（会有咔哒），改用双 LFO 交叉。

### 4.3 场景级（整个场景生命周期）：强度档位 + 微事件

- `plan.intensity` 映射密度/电平（见 §3.1），每 15–40 s 平滑过渡一次，产生「雨忽大忽小」；
- 每 3–6 分钟触发一次「微事件」：一次阵风、一次雷、一次车流高峰、一次虫鸣齐奏，持续 20–60 s 后回落；
- **同场景重复 apply 不再直接 return**：若 `scene` 相同但 `plan.seed` / `intensity` 变化，则触发一次「重构颗粒层」（重建事件调度器与随机种子），噪声床继续沿用（避免交叉淡化），这样场景不会「锁死」。

### 4.4 反循环的具体手段

| 循环来源 | 现状 | 新方案 |
| --- | --- | --- |
| 噪声 buffer 循环 | 2 s 单声道 | 16 s 双声道，首尾 1 s 等功率交叉淡化；生成时对尾部做淡入淡出保证无缝 |
| 同 buffer 多实例同相位 | 未处理 | 每个实例 `start(now, randomOffset)`，偏移取 `[0, 12)` 秒随机 |
| LFO 周期 | 0.025–0.12 Hz 固定 | 双 LFO 不可公度叠加 + 每 30–90 s 随机重设一个 LFO 的 `rate ±15%`（`cancelScheduledValues` 后 `setTargetAtTime`） |
| 事件间隔 | 均匀分布 | 泊松 + 簇发 |
| 滤波固定 | 从不变化 | 随机游走 |
| 立体声相同 | 单声道 buffer | 双声道独立噪声 + 每实例声像偏移 |

**验收标准**：离线渲染 5 分钟，自相关在 16 s、2 s、1 s 处的峰值 < 0.2；1/3 倍频程长期平均谱在 60 s 窗口间的漂移 > 1.5 dB（说明确实在变）。

## 5. 程序化 vs 采样：边界与清单

### 5.1 判据

程序化能做好的：**宽带噪声 + 共振峰 + 随机颗粒 + 慢速调制**（雨、风、火、水、虫、雷、室内）。
程序化做不好的：**有明确谐波结构且语义可辨识的声音**——人声（音素/共振峰过渡）、发动机（谐波簇 + 点火频率）、钟表（金属瞬态）。

因此采样优先级：

1. **人声嘈杂**（必需，程序化破绽最大）；
2. **车辆经过**（强烈建议，发动机谐波做不出来）；
3. 钟表（可选，程序化「嗒」已够用，采样更真）；
4. 其余全部程序化。

### 5.2 内置素材清单与体积预算

格式统一 **Ogg Opus**（`audio/ogg; codecs=opus`），单声道 48 kbps / 立体声 80 kbps；同时准备 **m4a/AAC 回退**（Safari 对 Ogg 容器支持不稳定），仅在人声/车流这类必需采样上提供，避免双份体积翻倍——回退文件可按需在构建时生成，不默认进包。

| 文件 | 时长 | 声道 | 码率 | 体积 | 用途 | 必要性 |
| --- | --- | --- | --- | --- | --- | --- |
| `crowd-babble-a.ogg` | 30 s | stereo | 80 kbps | ~300 KB | 酒馆/集市/人群 | 必需 |
| `crowd-babble-b.ogg` | 30 s | stereo | 80 kbps | ~300 KB | 与 a 随机错位叠加，破坏循环 | 必需 |
| `crowd-distant.ogg` | 20 s | mono | 48 kbps | ~120 KB | 远处人群/隔墙 | 可选 |
| `traffic-pass-01.ogg` | 8 s | mono | 64 kbps | ~64 KB | 单车经过 | 建议 |
| `traffic-pass-02.ogg` | 8 s | mono | 64 kbps | ~64 KB | 变体 | 建议 |
| `traffic-bed.ogg` | 30 s | stereo | 80 kbps | ~300 KB | 远处车流底盘 | 可选 |
| `clock-tick.ogg` | 4 s | mono | 48 kbps | ~24 KB | 钟表 | 可选 |
| `thunder-close-01.ogg` | 10 s | mono | 96 kbps | ~120 KB | 近雷炸裂（可选增强） | 可选 |

- **默认预算：约 1.3 MB**（必需 600 KB + 建议 128 KB + 可选全部）；
- **上限：2.5 MB 目标，6 MB 硬上限**（打包脚本断言）；
- 解码后内存：30 s 立体声 48 kHz ≈ 11.5 MB PCM。**同时解码缓冲不得超过 3 个（约 35 MB）**，用 LRU 淘汰；切场景时只加载当前场景需要的 0–2 个文件。

### 5.3 素材来源与许可（CC0 优先）

| 来源 | 许可 | 适用 | 风险 |
| --- | --- | --- | --- |
| **Freesound**（`license:"Creative Commons 0"` 过滤） | CC0 | 首选；crowd/traffic/clock 都有 | 必须逐条记录 **sound ID + 作者 + URL + 下载日期**；有些条目名义 CC0 但含第三方素材，需看描述 |
| **OpenGameArt** | CC0 / CC BY | 游戏音效，循环素材多 | CC BY 需署名 |
| **Internet Archive** | 多为 PD / CC0 | 老录音、环境录音 | 元数据不可靠，需逐条核 |
| **Pixabay** | Pixabay Content License | 数量多、质量好 | **不是标准 CC**；许可禁止「以独立形式转售/分发内容」，嵌进应用一般可接受但存在解释空间；且要求不得暗示背书。**不作为首选**，若使用需在报告/许可清单标注为「非 CC，Pixabay 许可」 |
| **爱给网/淘声网等国内站** | 站内「免费商用」多为站点自有协议 | 可作补充 | 常见限制：需授权书、禁止再分发、仅限特定用途。**默认不采用**，除非逐条核对条款并留存证据 |
| **自制离线渲染** | 项目自有 | 最安全 | 需要额外开发离线渲染脚本；不建议为「省许可」而牺牲真实感 |

**推荐策略**：人声/车流从 Freesound 取 CC0 条目，下载时把元数据写入 `data/assets/ambient/CREDITS.md` 与 `THIRD-PARTY-LICENSES.md`；找不到合适 CC0 时，用「自制录制/自制渲染」而不是 Pixabay/国内站。

### 5.4 加载与缓存

- 路由：`GET /assets/ambient/<filename>`，`Cache-Control: public, max-age=604800, immutable`，`send_from_directory`（自带 ETag / Range）；
- 前端：`fetch → arrayBuffer → ctx.decodeAudioData`，结果进 `Map<url, AudioBuffer>`；
- 预取：场景切换后 1–2 s 用 `requestIdleCallback` 预取「同组场景」的采样（如 crowd ↔ distant-crowd）；
- 失败降级：解码/网络失败 → 自动退回程序化 babble，`diagnostics().samples = "fallback"`；
- 低画质档（`quality >= 2`）不加载任何采样，纯程序化。

## 6. 主链与接口改动评估

### 6.1 主链（必须改，否则采样和次低频都白做）

| 现状 | 建议 |
| --- | --- |
| HP 90 Hz | **HP 28 Hz**（2 级，24 dB/oct），保护 DC 但保留雷的 30–60 Hz |

$ambientDir = Join-Path $App 'data/assets/ambient'
if (Test-Path $ambientDir) {

## 8. 实施顺序

| 阶段 | 内容 | 验收 |
| --- | --- | --- |
| **P0**（半天） | 噪声源：粉/棕噪双声道 16 s 交叉淡化 buffer + 多实例随机偏移；主链 HP→28 Hz、LP→16 kHz | 雨不再像雪花；雷有胸腔感 |

| **P5**（持续） | 听感调参、频谱回归 | 见 §9 |

**建议先做 P0+P1 后暂停听感评审**：这两步就能回答「还像不像雪花噪声」，再决定是否值得投入采样。

## 9. 验证方法

1. **频谱回归**（自动化）：`OfflineAudioContext` 渲染 60 s，取 1/3 倍频程平均谱：
   - 粉噪层斜率应为 −3 ±1 dB/oct，棕噪层 −6 ±1.5 dB/oct；
   - 雨在 600–1200 Hz 与 4.4–5.6 kHz 应有局部凸起（比相邻 1/3 倍频程高 ≥2 dB）；
   - 雷在 180–260 Hz 应有峰值；
2. **循环检测**：渲染 5 分钟，自相关在 1 s / 2 s / 16 s 处 < 0.2；
3. **演化检测**：相邻 60 s 窗口的谱差异 > 1.5 dB；
4. **事件速率**：`diagnostics().event_rate` 落在配方 λ 的 ±30%；
5. **主观盲测**：每场景 2 分钟，问「有没有听到重复」「像不像真实录音」，至少 3 人。

## 10. 风险

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 节点数暴涨（每层 3 滤波 + LFO + 事件） | 低端机爆音/卡顿 | `quality` 分档：≥1 砍到 2 层；≥2 纯单层无事件；事件全局上限 80 spawns/s |
| 次低频进入混音导致限幅器泵动 | 整体音量忽大忽小 | 雷走独立 `thunderBus`，经 28 Hz HP + 专用压缩；主链限幅器阈值复核 |
| 采样解码内存 | 移动端 OOM | LRU ≤3 个、30 s 上限、低画质不加载 |
| Ogg Opus 兼容性 | Safari 无声 | m4a/AAC 回退或直接程序化；`decodeAudioData` 失败自动降级 |
| 许可不清 | 分发风险 | 只用 CC0；Pixabay/国内站默认不用；逐文件登记 |
| 打包遗漏 | 用户听到「没环境音」 | `$required` 断言 + 缺目录时纯程序化 + `DEPLOYMENT.md` 说明 |
| 与另一条会话冲突 | 合并冲突 | 只新增文件 + 改 `ambient-engine.ts`；`index.ts`/设置面板不动 |
| 调参主观性强 | 反复返工 | 配方表参数化（场景数据与引擎分离），可快速 A/B |
