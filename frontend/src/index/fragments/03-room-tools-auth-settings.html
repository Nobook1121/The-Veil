KP 请求限制

达到限制时 KP 会自动收尾，并在聊天框与日志中给出说明，不会静默无响应。

请求被网络中断（未收到响应）时自动重试的最大次数，重试进度会显示在聊天框；0 表示不重试（0-20）。
同一轮发言内用相同参数重复调用同一工具时不再执行，直接复用上次结果，避免重复掷骰/重复触发。

最大输出 Token（全局）

所有平台共用的 max_tokens 默认值。请求模板（各模型 JSON）里若自行写了 max_tokens，以模板为准；没有写的，则统一按下值下发。

勾选：未在请求模板单独设置的请求统一下发下面的默认值；不勾选：不下发 max_tokens，完全交给平台自身（探针/连通性测试始终使用极小值，不受影响）。
仅在上方开关勾选、且请求模板未单独声明时生效（1-200000）。

本地响应缓存

相同输入 + 相同剧情状态下直接复用本地回复，命中即整次跳过上游请求，是最省 token 的方式。仅对无副作用输入（非检定/非触发/非转场）生效，不会让 KP 忽略剧本推进。

关闭后房间内对话每次都直连上游（主页聊天仍使用精确缓存）。
越大命中越多、越省 token，但过期内容被复用的窗口也越长（30-86400）。
主页聊天（无房间状态）的精确缓存有效期（30-86400）。

控制每次请求召回的章节数量、导入剧本的切块粒度，以及章节召回的新鲜度策略。

带场景模块的剧本每次召回的章节数量（1-32）。

子块越小召回越精确；章节超过该长度才继续切分（优先在段落边界）（200-8000）。
