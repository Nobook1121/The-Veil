# v1.0.7

## 地图导入、5e 自动化与插件文档收口

改动时间：2026-11-17（Asia/Shanghai）

### 版本

- 应用版本统一为 **1.0.7**，唯一真源为 `backend/trpg_server/version.py` 的 `APP_VERSION`。
- 历史 changelog 不改写。

### 一、地图

- **外部地图导入**：支持裸图片（PNG / JPG / WEBP / BMP）、Universal VTT（`.uvtt` / `.dd2vtt`）与 Foundry VTT 场景导出。UVTT 与 Foundry 会一并带出墙体、门 / 窗、光源、环境光与网格；Foundry 场景要求背景图内嵌，引用外部图片时会提示改用内嵌图片、UVTT 或裸图片。导入按文件内容识别格式，任一步失败都不会留下半个场景。
- **导入上限**：文件 64 MB、解码后图片 40 MB、单边 64–16384 px、总像素 1.2 亿；墙体 / 门 200 段、光源 100 个。超限会给出明确原因。
- **网格标定**：导入后确认格子数与偏移；格式记录的尺寸与图片不一致、墙体超出图片范围或使用非英尺单位时会提示复核，而不是替用户猜网格。标定修复后格线与地图不再错位。
- **场景与棋子坐标**：棋子使用「格坐标 + 格内偏移」，拖动后吸附网格，多格棋子按占位换算。
- **多场景**：支持新建空场景、复制当前场景与切换场景；场景之间的棋子、墙体、光源与迷雾完全隔离，切换场景不会中断房间级战斗与先攻；复制场景会重置迷雾。当前版本暂不支持删除场景。
- **断线重连**：连接恢复后重新拉取地图与迷雾，不再沿用断线前的内存副本；多人同时在线时以服务端最新场景为准。
- **墙体与视线**：移动与视线都会被墙体阻挡，门 / 窗按开关状态放行或拦截；人类玩家与 KP / AI 移动共用同一条校验链。没有棋子时，系统会明确标注「未做视线与墙体校验」，不会假装已校验。
- **战争迷雾**：默认按观察者分别记录探索，每名玩家只看到自己（或自己棋子）探索过的区域，玩家之间存在信息差；没有绑定棋子的玩家退回队伍视野，KP 可以看到全部。房主 / 管理员可以开关迷雾、在「按观察者 / 队伍共享」之间切换、调整视野格数或临时隐藏迷雾。旧版本的单份共享探索记录会作为基线保留；网格标定变化时，探索记录会失效并重置。
- **动态光源**：支持光源开关、明暗半径、颜色与墙体遮挡投影，地图按亮区 / 暗区分层显示；环境光与黑暗度随导入或手动设置生效。
- **写操作冲突**：地图写操作带幂等键与乐观锁回执，重复提交不会叠加移动或重复改状态；版本落后时会提示刷新，而不是静默覆盖。

### 二、D&D 5e

- **规则集与内容**：5e 以插件形式随包提供，SRD 5.1 的法术、怪物、装备、条件等内容数据由独立内容包提供；在「设置 → 插件」启用后，剧本可选「D&D 5e（SRD 5.1）」。
- **角色卡**：六项属性与调整值、豁免与技能熟练、职业与等级、熟练加值、HP / 临时 HP / AC / 速度、装备与武器、法术位与已知 / 准备法术；支持导出 / 导入，CoC7 卡不受影响。
- **d20 骰桌**：检定、豁免与攻击按 d20 呈现；优势掷两颗取高、劣势取低，两者同时存在时抵消；自然 1 / 20 高亮，历史消息静态还原。
- **行动经济**：每回合 1 个动作、1 个附赠动作、1 个反应与按速度计算的移动力；回合开始恢复，超出移动力会被拒绝且坐标不变。
- **死亡豁免**：生命归零进入濒死，回合开始掷死亡豁免；自然 20 恢复 1 点生命，自然 1 记两次失败；三次成功稳定、三次失败死亡，濒死再受伤会累加失败。
- **法术位与专注**：按职业与等级记录法术位，支持升环；受伤自动触发专注检定，也可主动解除，昏迷或死亡自动中断；战斗外施法按游戏时间到期。
- **状态与力竭**：条件、力竭分级、持续时间与结束时的重复豁免按 SRD 结算，攻击、豁免与移动修正自动生效。
- **升级规划**：升级分为「预览」与「应用」两步：先按职业与目标等级生成可选槽位（属性提升 / 专长、法术等），确认后一次性校验并落库；预览会过期，角色卡在此期间被改动时会要求重新预览，避免写坏卡。
- **内容检索与消歧**：检索法术、怪物与装备时会带出环阶、CR、装备类别等区分信息，同名或近似条目会列出候选让 KP 选择，而不是默认取第一条；自带检索源的规则集会参与回合预取，结果附来源与许可，与上传规则书的检索结果合并。
- **检定入口**：房间检定按规则集分派，d20 规则集掷 d20（支持 DC、优势 / 劣势），百分制规则集保持原有百分骰，同一条聊天命令不会在两套规则间走错链路；KP 的主持提示词也按房间规则集组装。
- **休息与装备**：短休消耗生命骰回血，长休回满生命、恢复一半生命骰与法术位、力竭降一级并结束专注；装备 AC 按无甲 / 轻 / 中 / 重 / 盾与数据包计算，力量不足扣 10 尺速度，未穿戴装备不计入；同调上限 3，只能在休息期间建立，可随时解除。
- **房规生效**：暴击规则、先攻方式、突袭、夹击、掩体、变体负重与法术点制都会真正进入结算，休息变体决定短休 / 长休时长；未接入结算的死亡豁免公开、对角线移动与 1 级专长三个字段已移除，避免「配置了但不生效」。
- **规则集切换**：切换规则集不再因战斗进行中报 409。系统会按顺序归档当前战斗（写入战斗归档，最多保留最近 20 场，并在房间状态里标记为「已结束」、结束原因为规则集切换）、取消未结束的工作流（含等待中的反应窗口、豁免与续跑）、结束各场景的持续区域，然后继续命名空间迁移、默认房规初始化，并暂停不兼容的角色卡绑定。只要规则集确实发生变化，即使当前没有战斗，旧规则集遗留的等待流程与持续区域也会被结束。切换响应与房间日志会带上归档标记与取消 / 结束计数；只有目标规则集未知或未启用时才返回 409。

### 三、自动化

- **统一服务端流程**：施法与攻击由服务端工作流推进，依次完成校验、结算、附加效果与专注登记；AI 与真人共用同一条流程，客户端无法绕过。
- **策略**：每一步按「自动 / 询问 / 手动」执行，并按执行者真正生效：自动直接结算；询问在批准后执行登记的处理器，拒绝则按取消处理；手动只记录决定本身。缺少处理器的自动步骤会显式失败，不会被当成成功。默认攻击与伤害自动结算，豁免与反应询问当事人，KP 控制的目标直接结算；策略可按房间覆盖，非法执行者或策略会被拒绝。
- **幂等与超时**：攻击额外支持 `request_id`；不传时按回合、攻击者、目标、武器与槽位生成稳定键，AI 重试会命中同一流程。重复提交直接返回既有结果，不会重复扣血、重复扣行动预算或再消耗法术位。步骤默认 120 秒超时，超时后反应按「不反应」、豁免按「不通过」收尾；续跑会同步续期角色卡锁，锁已丢失时流程显式失败；过期流程先收尾再释放锁，向过期流程重复提交会被拒绝。
- **豁免待决**：需要玩家掷豁免时流程真正暂停并进入待决队列，玩家投掷或超时后再继续，不再出现「等不到结果就继续」。
- **反制**：反制法术进入反应窗口，高环反制改为施法属性检定自动结算，结果写回流程事件。
- **护盾术**：护盾术作为反应插入攻击结算，在命中判定后、伤害结算前改变 AC，并按反应额度扣减。
- **持续区域**：球、立方、柱、锥、线、方、圆等区域可跨回合存在，进入、回合开始或回合结束自动触发；每个目标每回合最多触发一次，到期自动清理；没有地图时会跳过自动触发而不是臆测位置。

### 四、插件体系

- **插件 UI 宿主**：插件可以声明房间主视图的挂载点与前端资源，宿主按房间规则集与用户权限自动挂载；未启用的插件不会加载资源。
- **系统插件分组**：设置页「插件」分为「系统插件」与「第三方插件」；CoC7 作为随包系统插件只读显示，不参与启用、禁用或卸载；5e、SRD 内容包与地图作为第三方插件可单独启用与回滚。
- **文档**：补充插件开发文档与第三方插件使用说明，覆盖清单字段、能力声明、启用 / 禁用 / 卸载、回滚方式、安全边界与示例插件；地图与 5e 的安装顺序、依赖关系与排障也在文档中说明。
- **规则集严格解析**：房间视图、房规、战斗配置与插件 UI 槽位都按房间实际启用的规则集解析；未知或未启用的规则集不会再悄悄回退到 CoC7，而是返回 409 与可读原因。规则集专属工具与自动化工具由插件声明，核心不写死某套规则。

### 五、安全与稳定性修复

- **工作流鉴权**：工作流的决定只能由角色本人、AI 执行者或 KP / 房管提交；取消与强制超时只允许发起者或 KP / 房管。操作者身份由会话派生，不接受请求体自报。
- **迷雾探测**：`spatial/line` 在迷雾下只判断可见范围内的目标，范围外不判定，也不返回墙体 id。
- **信息可见范围**：移动占位冲突对非管理者使用中性文案，不泄露隐藏棋子名；工作流列表与详情按角色裁剪，事件日志仅 KP / 房管可见。
- **成员退出**：成员被移除或退出时真正离开实时房间，不再依赖全量状态回退广播兜底。
- **房间写锁**：地图、战斗、时钟、叙事与工作流统一使用房间级写锁，锁定顺序固定为「角色卡锁 → 房间锁」，避免死锁与互相覆盖；消息追加在同一把锁内完成，不再丢消息。
- **AI 玩家接管**：只允许房主 / 房管或该 AI 的原创建者接管，普通成员请求会被拒绝。
- **检定超时卡在「正在整理回复」**：等待投掷超时后，未投掷则自动投掷并确认，已投掷则确认最后结果；自动投掷失败也会结束本次检定并让 AI 继续回复。
- **AI 托管与 AI 玩家**：房主可把真人成员切换为 AI 托管、添加 AI 玩家；AI 回合在服务端直接结算，不等待真人投掷；AI 行动后可自动追加队友回合，但不会反向触发 KP。接管 AI 角色需要房主 / 房管或该 AI 的原创建者身份。
- **在线人数**：在线状态按 socket 维护，多标签页关闭不再误判离线；成员列表与消息徽标区分 AI 玩家和真人，在线人数统计与实际在线一致。
