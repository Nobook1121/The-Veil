## 首次部署引导（Embedding 模型）

- 向导由 5 步扩为 6 步，第 2 步「准备 Embedding 模型（可跳过）」提供三种方式：程序自动下载（后台线程，官方站失败自动回落镜像）、拖入模型文件夹 / `.zip` 压缩包上传、复用已配置的 AI 平台改用其 embedding 接口；跳过按钮与其它步骤保持一致。
- 新增独立模块 `setup_embedding.py`（下载任务状态机、仓库文件枚举、zip / 散文件落盘、`general.toml` 开关写入）与 `routes/setup.py` 的 4 个接口（status / download / upload / cloud）；新路径加入 CSRF 与会话豁免名单。
- 引导上传体积上限独立为 `SETUP_EMBEDDING_UPLOAD_MAX_BYTES`（256 MB），全局 `MAX_CONTENT_LENGTH` 改为取各功能上限的最大值，不再由剧本导入上限单独决定。
- **模型仓库不再写死**：默认值改由 `general.toml` 的 `[ai] local_embedding_repo` 决定（代码内仅保留兜底默认值），`GET /api/setup/embedding/status` 回传当前生效值，引导页据此动态显示仓库名，前端文案不再硬编码仓库名。
- 本地模型与云端 Embedding 都在程序下次启动时生效。

## 全局最大输出 token

- `general.toml` 的 `[ai]` 新增 `constrain_max_tokens`（默认开启）与 `max_tokens`（默认 16384）：未在请求模板里自行声明的请求统一按该值下发，模板里显式写了 `max_tokens` 的以模板为准；关闭开关则不下发 `max_tokens`，输出上限交给平台自身。默认取宽裕值是为了避免靠压缩输出预算省 token 而截断回复。
- 新增 `agents/ai_request.py` 统一请求封装，KP 对话、模块摘要、剧本处理、平台探测与角色卡生成共用；管理员设置页新增「最大输出 Token（全局）」区块，保存确认后生效。

## 骰桌降级、数量上限与 WebGL 实例治理（变更时间 2026-10-21 20:50）

- **不常见面数不再空白**：修复降级顺序缺陷——旧代码先创建简易舞台、再销毁 3D 实例，而 3D 销毁会清空整个骰桌容器，把刚插入的简易舞台一起删掉。现在先销毁旧渲染器再创建后备渲染器，3D 销毁只移除自己的 canvas；`d5` 等自定义面数由简易渲染器用通用骰面 + 数字兜底，并记录 `unsupported_dice:*` 降级。
- **骰子过多改为桌面提示**：新增 `DICE_SIMPLE_RENDER_LIMIT`（60 枚），超过时不再尝试渲染（3D 上限 20 枚、简易也不能无限堆 DOM），在骰桌区域显示「骰子数量过多，无法在骰桌上渲染，仅显示下方结果」，结果数字仍正常显示；`100d100` 展开的 200 枚骰子不再出现整桌空白，降级上报原因新增 `dice_count_exceeded`。
- **刷新后历史骰桌完整**：历史静态还原不再因骰型不支持而跳过渲染；投掷者兼容对象形式 `{user_id, username}`，修复所有历史骰桌刷新后显示 `[object Object]` 的问题。

## 修复 Windows 下 JSON 原子写 PermissionError（变更时间 2026-10-21 21:57）

- **现象**：`POST /api/rooms/<room_id>/messages` 在 `json_store.write_json_atomic` 的 `os.replace` 处抛 `PermissionError: [WinError 5] 拒绝访问`，接口返回 500，消息写入失败。
- **原因**：Windows 的 `MoveFileEx` 替换目标文件时需要独占删除权限。目标 `messages.json` 被另一进程/线程短暂打开（并发读写、杀毒软件或索引器扫描），或同一 `data/runtime` 上同时运行了多个服务实例时，替换就会失败；该错误是瞬时的，与文件内容无关（文件并非只读）。
- **修复**：`json_store` 新增 `replace_with_retry`，`write_json_atomic` 与房间日志 `room_log._write_entries` 统一改用：Windows `WinError 5/32` 按 0→0.02→0.05→0.1→0.2→0.3→0.5→0.8 秒递增重试（最长约 2 秒），`WinError 5` 时先尝试清除只读属性；重试成功写一条 `json_replace_retried` 警告日志便于排查；临时文件清理失败不再覆盖原始异常。
- **运维**：同一 `data` 目录同一时间只应运行一个服务实例，避免两个进程同时写同一房间文件。

## 骰子静止后不再操作，只读取朝上的面（变更时间 2026-10-21 23:13）

- **现象**：3D 骰子落定后仍会「被提起来转一下」，顶面点数在静止后发生改变。
- **原因**：`animateRoll()` 在物理判定静止后进入 `settle` 阶段，用 220ms `quaternion.slerp(target)` 把每枚骰子旋转到服务端结果对应的面——用户看到的就是落定后的二次旋转。简易档位同样在抖动结束后播放 `.settled` 位移/缩放关键帧。
- **修复**：删除整个 settle 阶段与 `SETTLE_MS`。物理静止后立即对刚体 `sleep()` 并结束，不再旋转、抬起、缩放或补间；新增 `syncUpFaceLabels()`，在骰子接近静止与最终静止时读取当前朝上的面（面法线经 mesh 四元数旋转后 y 分量最大者），把本次结果贴到该面材质上，同时还原上一张朝上面的贴图，保证「顶面点数 = 下方结果」。滚动过程中骰面照常随翻滚变化，不受影响。
- **简易档位**：删除 `.dice-simple-die.settled` 与 `@keyframes dice-simple-settle`，`play()` 不再等待 280ms 落定动画，抖动停止后原地显示最终点数。
