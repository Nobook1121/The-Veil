# v1.0.4

## 道具工坊：PDF 道具、AI 起草、备道具、生图与用户模板

改动时间：2026-11-12（Asia/Shanghai）

### 版本

- 应用版本统一为 **1.0.4**，唯一真源为 `backend/trpg_server/version.py` 的 `APP_VERSION`。
- 历史 changelog 不改写。

### 一、道具工坊（P0–P6）

新增完整的房间道具工坊：把线索、信件、票据等做成可查看、可投递的 PDF 道具。

- **P0 渲染底座**：新增 `props/` 包，包含模板注册、原子存储、可见性策略与 PyMuPDF `Story` 渲染；渲染使用 `threading.Semaphore(2)` 限流，纹理由 `scripts/gen-prop-textures.py` 生成。
- **P1 接口与配置**：新增 `routes/props.py` 九个接口（模板、列表、创建、更新、删除、预览、渲染、揭示、撤回）与 `[props]` 配置键 `enabled`、`max_props_per_room`、`max_field_chars`、`image_daily_budget`、`render_cache_days`、`ai_draft_enabled`、`auto_prepare_on_import`；接口 500 统一带 error 码与 trace_id。
- **P2 道具袋与编辑器**：新增 `prop-api.ts`、`prop-library.ts`、`prop-editor.ts`、`15-props.css`，支持 12 种模板、字段编辑、做旧滑块、纸张样式与 KP 预览。
- **P3 投递与卡片**：新增 `prop-card.ts` 与查看器，`messages.json` 新增 `type: "prop"` 消息；前端对未知消息类型有兜底。
- **P4 AI 工具与防剧透**：新增 `props.create` / `props.reveal` / `props.update` 三个 Agent 工具；只在启用道具工坊时注入短提示词；AI 上下文只拼 revealed 版本并统一 `████` 脱敏，未揭示道具返回「该道具不存在或不可见」；单回合最多创建 1 件，房间上限返回明确拒绝文本。
- **P5 AI 起草 / 备道具 / 生图**：编辑器新增「让 AI 起草」，单次小请求、失败重试一次且不阻塞编辑器；剧本导入后可把 `clue` 模块映射为 `scenario-<id>/prop-packs/<pack_id>.json`，由 `auto_prepare_on_import` 控制；`photo` 模板复用 `immersive` 生图平台链路，按 `image_daily_budget` 限额、同 prompt hash 复用，失败降级为空白照片框。
- **P6 12 个模板**：补齐 `letter-1920`、`diary-page`、`note`、`newspaper`、`telegram`、`invitation`、`dossier`、`ticket-stub`、`receipt`、`evidence-tag`、`photo`、`contract`；模板 order/group 稳定，新增装订孔、撕口、烫金花边三张纹理；各模板正常内容均 1 页，测试上限 3 页且无方块字。

### 二、用户模板扩展

- 模板来源改为「内置 + 用户」：内置 `backend/trpg_server/props/templates/`，用户 `data/props/templates/<template_id>/`。
- 用户模板同样包含 `manifest.json`、`page.html`、`style.css`、可选 `assets/`；`templates` 接口每条返回 `source: "builtin" | "user"`。
- id 冲突时内置优先，用户模板跳过并 warning；校验失败只让单个模板不可用，`unavailable` 返回 `id`、`dir`、`source`、`reason`。
- 安全校验：`page.html` 只允许文档流标签（`div/p/span/h1–h4/table/tr/td/ul/ol/li/hr/img/strong/em`）与有限属性；禁止 `<script>`、`<iframe>`、`on*`、`javascript:`、外链 `url(http...)`、`@import`；`assets/` 只收真实 PNG/JPEG，单文件 ≤ 5 MB、总量 ≤ 20 MB、最多 24 个；所有路径经 `safe_join`，`..` 拒绝。
- 新增 `POST /api/props/templates/rescan` 与编辑器「重新扫描」按钮，放完模板无需重启；用户模板在模板选择器中单独分组。

### 三、插件扩展体系

新增可复用的第三方插件体系，其他开发者不改核心代码即可扩展道具模板、规则集、Agent 工具与 HTTP 接口。

- **统一清单规范**：插件目录为 `data/plugins/<id>/`，清单 `plugin.json` 描述 `id`、显示名、`version`、`api_version`、目标 App 版本区间 `requires.app`、依赖 `requires.plugins` / `dependencies`、冲突 `conflicts`，以及能力 `capabilities`（`prop_templates` / `rulesets` / `agent_tools` / `http_blueprints` / `settings_sections` / `frontend_assets`）。JSON Schema 见 `docs/schemas/plugin-manifest.schema.json`，与校验实现保持同步。
- **生命周期与失败隔离**：发现 → 清单校验 → 版本/依赖/冲突检查 → 拓扑排序 → 资源审计 → 激活能力 → 启用/禁用/卸载。任一插件在任一步失败只把自己（及依赖它的插件）标为 `failed` 并写日志，主程序照常启动；`GET /api/plugins` 列出 `loaded` / `disabled` / `failed`，带 `reason_code` 与可读 `reason`。
- **默认不启用与回滚**：`data/plugins/enabled.json` 是唯一启用来源，未启用插件只读取清单用于展示，不读资源、不 import 代码。一键禁用全部第三方插件有三种方式：启动参数 `--no-plugins`、环境变量 `TRPG_PLUGINS_DISABLED=1`、`create_app({"PLUGINS_DISABLED": True})`。
- **信任与安全边界**：插件代码以宿主进程权限运行，信任边界是管理员显式安装并启用；所有路径经 `safe_join`，插件目录及内部符号链接一律拒绝；单插件 ≤ 512 文件 / 64 MB、入口模块 ≤ 16 MB、清单 ≤ 128 KB。
- **模板能力边界**：道具模板来源由「内置 + 用户」扩展为**内置 → 插件 → 用户**三级，优先级同序；插件模板 `source` 为 `plugin:<插件 id>`，`data/props/templates/` 仍作为不含 Python 的轻量模板包路径保留。
- **示例与文档**：最小可用示例 `examples/plugins/hello-prop/`（便条模板 + 只读 HTTP 接口）；开发文档 `docs/plugin-development.md` 覆盖目录结构、manifest 字段、各能力接口、版本兼容、错误码、调试与安全模型；定向测试 `tests/test_plugins.py`。
- **已知限制**：代码插件（`http_blueprints`）禁用后已注册的路由仍在，需重启服务才能完全回滚（接口返回 `restart_required`）。
