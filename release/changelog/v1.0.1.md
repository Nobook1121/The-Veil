改动时间：2026-11-08（Asia/Shanghai）

### 一、现状比对结论

逐条对照后分为三类：

**已符合（未改动）**

- DEX 降序先攻、同值由战斗技能高者先（p86）。
- 近战对抗的成功等级比较；闪避平手视为未命中、反击平手仍命中、反击等级更高时先挡开再还击（p86-87）。
- 单轮一次显著行动；闪避/反击每轮各一次（p86）。
- 战技体格差惩罚与寡不敌众的奖励骰（p89、p91）。
- 射击距离难度、故障值、贯穿（p95-98）。
- 伤害先扣护甲、重伤阈值半耐久、重伤 CON 检定昏迷（p100-101）。
- 即死为单次伤害**大于**最大耐久；濒死要求「先重伤且耐久归零」同时成立（p100-101）。
- 无独立「格挡」动作；近战被攻击只有闪避或反击（p86-87）。
- 急救/医学的难度与时限（p101）。

**与规则书冲突（已修正）**

**项目自定房规（保留并显式配置）**

- DEX 阈值额外行动、突袭自动成功、拔枪耗时、施法打断方式、施法时能否防御、重伤是否禁止行动、盾牌/格挡别名、濒死轮末检定。
- 均已写入房间房规 `HOUSE_RULE_DEFINITIONS`，默认值为“规则书未规定时最保守的解释”。

### 二、新增房规键

- `combat_surprise_model`：`bonus_die`（默认，首轮近战 1 奖励骰）/ `auto_success`。
- `combat_ready_weapon_cost`：`free`（默认）/ `action` / `round`。
- `combat_cast_interrupt`：`keeper`（默认，规则书原文为 KP 裁定）/ `any_damage` / `never`。
- `combat_cast_defense_allowed`：默认 `false`。
- `combat_major_wound_penalty`：`none`（默认）/ `cannot_act`。
- `combat_shield_action`：`disabled`（默认，核心无盾牌条目）/ `counter_alias`。
- `combat_dex_extra_action_threshold`：默认 `null`；**不是核心规则**。
- `combat_dying_check`：默认 `true`。

### 三、插件边界与取舍

- 新增 `backend/trpg_server/combat/`：
  - `contracts.py`：`CombatRuleset` 协议 + `CheckOutcome` / `DamageOutcome` / `RoundEndOutcome`。
  - `settings.py`：`CombatSettings`，只承载规则书留白与房规开关。
  - `scheduler.py`：`TurnScheduler`，核心只负责回合推进、行动次数、跳过失能者与轮末钩子。
  - `registry.py` + `rulesets/coc7.py` + `rulesets/dnd5e.py`。
- 可替换的五块：先攻与行动经济（`roll_initiative` / `actions_per_round` / `action_budget` / `is_incapacitated`）、判定与对抗（`resolve_melee` / `resolve_attack`）、伤害与死亡（`resolve_damage` / `on_round_end`）、资源与状态（`spend_resource`）、法术与能力（`spell_timing`）。
- 核心不出现 HP / SAN / MP 字段名，只有“有效伤害、行动槽、资源扣除与溢出”这类事实。
- **保留在 CoC7 插件内、没有强行抽象的部分**：成功等级（大成功/极难/困难/常规/失败/大失败）、贯穿与伤害加成、重伤/濒死/即死语义、SAN 损失与疯狂判定、武器表字段。理由：这些语义只在 CoC7 内自洽，抽成跨规则书接口会丢失“成功等级 + 贯穿 + 重伤”的组合含义，属于“为了形状整齐拆坏能用的东西”。
- `dnd5e.py` 是参考插件（d20 先攻、action/bonus/reaction/movement、对 AC 命中、死亡豁免），用于证明协议不依赖 CoC7 字段；房间面板仍只启用 CoC7（`COMBAT_RULESETS = ("coc7",)`），接入 5e 角色卡后再放开。

### 四、行为与接口变更

- 新增工具与 HTTP 动作：`combat.delay` / `combat.disengage` / `combat.reload` / `combat.ready` / `combat.cast`，战斗面板增加「延迟 / 脱离 / 装填 / 准备武器」按钮。
- 战斗状态新增字段：`actions_remaining`、`actions_per_round`、`reactions_this_round`、`ready_weapon`、`disengaged`、`dying`、`ruleset`。
- 施法：先扣 MP/SAN（打断不退），MP 不足的溢出按 1:1 扣 HP；`instant` 法术 DEX+50，`two_rounds` 次轮生效。
- 重伤房规为 `cannot_act` 时，攻击、射击、延迟、脱离、装填、准备武器、施法全部被拒绝。
- 突袭提示由「跳过行动」改为「仅修正攻击检定，不跳过行动」。

## 沉浸设置五处收尾修复

改动时间：2026-11-08（Asia/Shanghai）

### 一、房规成员白名单改为标签输入

- **根因**：`#houseRuleWorldOverrideUsers` 是原生 `<select multiple>`，浏览器里要按住 Ctrl/⌘ 才能多选，用户直接点击只会替换当前选中项，看起来「不可多选」。
- **改法**：与管理员「允许的音频块」复用同一个标签控件（`TrpgAudioBlocks`，allow 模式）。输入即筛选成员（按姓名、角色名宽松匹配），点选或回车加成 chip，chip 可点击 `×` 移除，`↑`/`↓`/`Esc`/退格/点击外部收起的行为与音频块控件完全一致。
- 控件新增 `placeholder` / `hint` / `noun` / `allowEmptyNotice` 四个可覆盖项，成员场景把提示语改成「成员」，并隐藏音频块专用的说明；保存时改由 `getSelection()` 读取 user_id 数组，提交字段不变。

### 二、音频块下拉去掉「配乐四选一」徽标与说明

- **根因**：`renderMenu()` 为每个候选项固定输出一个 `可叠加` / `配乐四选一` 徽标和一行 `description`，信息重复且占了半屏。
- **改法**：下拉项只保留块名称；不可用项仍保留禁用原因（「管理员未允许该块」「尚未接入音乐生成服务」等）。说明文本不再参与展示，但仍保留在数据里用于关键词匹配。

### 三、「启用程序化实时配乐」并入「允许的音频块」

- **根因**：`immersive.music_enabled` 复选框与「允许的音频块」表达同一件事（是否用配乐），是两个入口说两件事。
- **改法**：删除 `#immersiveMusicEnabled` 复选框及其绑定/回填；把「允许的音频块」整块移到 `实时配乐` 标题下原来的位置。保存通用设置时按清单派生 `music_enabled`：清单含 `procedural` / `music_model` / `external` 任一即为启用，只有环境音/静音即为关闭；清单为空时保持后端按旧配置推导，避免误关。

### 四、修正可触发事件条目的背景色

- **根因**：`.room-narrative-trigger` 用的是 `var(--bs-body-bg, #fff)` 与 `var(--bs-border-color, #dee2e6)`，但项目从未定义 `--bs-*` 变量，于是深色主题下永远落到 `#fff` 白底。
- **改法**：改用主题 token `var(--color-panel-muted)` / `var(--border-subtle)`，没有叠加 `!important`。

### 五、停止控制台刷 `narrative.bundle.load`

- **真实触发源**：房间叙述面板每 4 秒轮询一次，每轮先请求 `GET /api/rooms/<id>/narrative`，房主/管理员再请求 `GET /api/rooms/<id>/triggers`（图里两条日志相隔约 16ms 即这两个请求）。两个端点都会经 `NarrativeRuntime.load` → `load_bundle()`，而 `load_bundle()` 在**缓存命中时也会写一条 `bundle.load`**（`cached: true`、`latency_ms` 约 0）。所以刷屏不是重连或重绘，而是「轮询 + 命中缓存也记日志」。
- **改法**：后端缓存命中分支不再写日志，只在真正解析/重载 bundle 时记录；前端按状态签名（当前地点 + 已揭示线索，正好是可用触发器的全部输入）去重，签名没变就不再请求 `/triggers`。触发成功后清空签名强制重取。控制台现在只在 bundle 真正重新加载时输出。

### 六、验证

- `npm run typecheck`、`npm run build:frontend` 通过。
- `pytest tests/test_narrative_builder.py tests/test_narrative_runtime.py tests/test_narrative_trigger_runtime.py tests/test_room_narrative_routes.py tests/test_room_narrative_commands.py tests/test_immersive_audio_blocks.py`：**59 passed**（含新增的「缓存命中不写日志」用例）。
- 组件级静态页（真实 DOM + 编译后的 `audio-blocks.js` + 真实主题 CSS）验证标签控件、徽标/说明移除与条目背景色；构建产物 `dist/public/index.html` 已确认 `#immersiveMusicEnabled` 不存在、「允许的音频块」位于「实时配乐」标题下。
- 真机登录仍被凭据挡住，五条中的前端三条以组件级静态页覆盖，后端一条（日记刷屏）以 pytest 覆盖。

- 归一化：大小写不敏感，`_`、`-`、`/` 视为分隔符忽略；多关键词按「全部命中」处理；命中优先级为精确键/别名 > 中文名前缀 > 键子串 > 别名子串 > 名称子串 > 说明子串。

### 三、互斥与可见反馈

## 配乐设置改为可组合的「音频块」模型

改动时间：2026-11-07（Asia/Shanghai）

### 版本

- 继续并入 **1.0.1**（`v1.0.1` 尚未打 tag、也未创建 GitHub Release）。

### 一、块的定义与规则

- 新增五个音频块：`ambient`（环境音）、`procedural`（程序化生成配乐）、`music_model`（音乐生成模型）、`external`（外链 BGM）、`off`（不使用/静音）。
- **环境音可叠加**：可与任意配乐块共存，并继续受每个用户自己的环境音开关控制。
- **配乐四选一**：`procedural / music_model / external / off` 互斥；解析层会保证最多一个配乐块，房间 UI 也只允许单选。
- `music_model` 只有在「模型设置 → 平台」中启用了声明 `music_model` 用途的平台后才可选；未接入时管理员/房间两端都显示为禁用，并附「尚未接入音乐生成服务」的原因，不是点了没反应的死块。
- 项目不内置音乐生成适配器。即使平台已接入，当前版本也不会偷偷回落到程序化：解析结果给出 `music_model_pending` 与可见提示，由管理员/房间改选其他块。

### 二、数据模型与迁移映射

- 管理员（`general.toml [immersive]`）新增 `audio_blocks_allowed`（逗号分隔块清单），表示「允许什么」；管理员不决定房间实际用哪个。
- 房间房规新增 `immersive_audio_blocks`（块数组），表示「设置什么」；解析时与管理员清单求交集，房间永远是管理员的子集。
- 旧键保留读取兼容：
  - `music_engine` → 默认配乐块：`procedural→procedural`、`external→external`、`off→off`；
  - `music_engine_allowed` → 允许清单：映射 `procedural→[ambient,procedural]`、`external→[ambient,external]`、`off→[ambient,off]`，并保留 `off` 以维持房间可关闭；
  - 未显式配置 `audio_blocks_allowed` 时按上述规则推导；旧站点为 `off` 时不会被重新点亮。
  - 房间旧键 `immersive_music_engine` → `[ambient, <engine>]`；下次保存房规时写入新键并清空旧键。
- 升级后默认组合 = 环境音 + 旧引擎对应的配乐块，因此已有部署不会突然变静音。

### 三、两端 UI

- 管理员设置（实时沉浸 → 音乐）改为 Discourse 风格块清单：每个块显示名称、说明、移除按钮，底部下拉框只列出尚未添加的块；不可用的 `music_model` 在下拉中禁用并注明原因。
- 房间设置使用同一控件，但候选项只来自管理员允许清单；房间选中的块被管理员收回时，选择器保留原选择用于提示，同时显示「当前生效：…」与降级原因。
- 用户个性化新增「BGM 来源：优先播放房间 BGM / 优先播放自己的 BGM」，与个人 BGM 库的优先级设置共用同一份本地偏好；个人「配乐」开关仍只影响自己。

### 四、生效逻辑（不只写在 UI 上）

- `resolve_audio_blocks(settings, house_rules, music_model_available=...)` 统一解析：
  - 站点关闭 → 全部关闭（`site_music_disabled`）；

### 一、音乐长时间停在一个音上：量化与修复

- **旧实现的数据**（Node 复算真实编排产物，非估算）：和声节奏固定为 bed 4 小节 / rise 2 / tail 3 / climax 1。horror 44 BPM 每小节 5.45 秒，bed 段一个和弦持续 **21.8 秒**，实测最长同和弦连续 **32.7 秒**；所有档位最长同音响 12.8–28.0 秒、同和弦 18.5–33.1 秒。段内低音在 bed/tail 整段锁在同一个 pedal 上，horror 达 43.6 秒。
- **根因**：和声节奏以「小节」为单位写死，速度越慢、停滞越久；bed/tail 的低音整段是单一 pedal；段落内部没有内声部，pad 之外没有推进层。
- **修复**：
  - 和声节奏改为按秒折算：`HARMONY_SECONDS = { bed: 6, rise: 4.5, climax: 3, void: 99, tail: 5 }`，`rhythm = clamp(round(target / barDuration), 1, 4)`；并新增「同和弦最多重抽 4 次」的约束，避免进行本身退化成连续同和弦。
  - 内声部 `MotionPlan`：无前景动机的小节进入 2–3 个和弦音（bed 三音→五音、rise 级进上行、climax 五音→三音→根音、tail 回落），走 `pluck`/`organ`/`bell`，增益 0.085–0.105，只在后半小节出现，不抢前景。
  - 低频 `PulsePlan`：suspense/unease 用时钟点，horror/aftermath 用 62→44Hz 双 thump 心跳，留白段保留一条极稀疏心跳；urgency 保持 16 分 ostinato 不叠心跳。
  - bass 的 pedal 改为「2 小节一块」在主音与属音之间交替（I–V pedal），不再整段锁死一个低音。
  - 颗粒织体 `texture`、高潮 `impact`、进入高潮前的 `riser` 作为预渲染 buffer 层接入（见「四」）。
- **修复后数据**：同和弦最长 daily 9.23s / suspense 11.61s / unease 8.89s / horror 10.91s / urgency 5.45s / sorrow 8.28s / awe 10.59s / aftermath 8.57s；同低音最长 10.91–13.33s（旧 horror 43.6s）；段内同音响最长 5.75–11.66s。

### 二、播放一段时间后戛然而止：根因与证据

- **根因 1（主因）**：`void` 留白段旧实现被强制 8 小节。horror 每小节 5.45 秒，等于 **43.64 秒**几乎没有和声：段内全部 `chord = null`（没有 pad、没有低音），动态曲线降到 0.06，并且每 3 小节还有一处 `silence` 全静音；`playMotif` 当时被 `bar.chord` 守卫整段丢弃，只有极轻的 drone 和偶发钟声。这就是「播到一段时间突然没了、隔很久才回来」——按 horror 185.5 秒一轮循环算，每轮约在第 131–175 秒出现。
- **根因 2（换歌/中途加入）**：`playBridge` 只在「目标小节本身有和弦」时铺过渡垫。共享播放位置如果正好落在留白小节，旧总线此时已经淡出，新总线整小节不发声，最多再静音 5.45 秒。
- **排除项**：调度器没有断供。按 220ms tick、2.2s lookahead 复刻 `scheduleUntil` 推进 2 轮循环：horror 1686 个窗口、共排 69 小节，提前量始终在 0–5.45 秒之间，从未为负（没有跳小节），也没有连续空窗；`AudioContext` 挂起不在本次复现路径内，但已补上恢复分支。
- **修复**：
  - `void` 按秒收敛：`BREATH_SECONDS = 7.5`，`clamp(round(7.5 / barDuration), 2, 4)` 小节，horror 由 43.64s 降到 **10.91s**，其余档位 6.15–8.89s。
  - 留白不再有 `silence` 小节：改为「抽掉和弦 + 总线压到约 -17dB + 保留心跳/颗粒/钟声/混响」，任何时刻都有声，不会出现硬静音。
  - 总线电平：无和弦小节改用 `base × (0.10 + dynamic × 0.5)`，有和弦仍是 `base × (0.22 + dynamic × 0.85)`；去掉旧的 void `+0.12` 补偿。
  - `playBridge` 找不到和弦时向前回溯最近一个有声小节，仍找不到则用主音三和弦兜底，保证换歌不会先静音一小节。
  - 换歌切入位置避开无和弦小节：`audibleOrdinal()` 向前顺延到最近的有声小节（所有客户端算法一致，不破坏房间同步）。
  - 健康检查：`AudioContext` 处于 `suspended` 时 `resume()` 并跳过本拍；所有总线结束但仍有活动 plan 时重建总线，而不是让调度器静默退出。
- **修复后数据**：全部可听事件（pad 覆盖 + 动机/内声部/心跳/钟声/颗粒，事件按 0.28s 计）之间的最大空档 daily 2.03s / suspense 2.62s / unease 3.05s / horror 3.81s / urgency 1.54s / sorrow 2.82s / awe 2.37s / aftermath 2.93s（旧 horror 42.9s）。留白段的最大「无和声」时长 5.66–10.16s，但期间仍有织体、心跳与混响。

### 三、环境音（P2）落地

- 新增 `ambient-engine.ts`，**零音频资源**：全部由噪声整形合成。
- 9 个场景：`interior / street / storm / wind / dread / rain / fire / forest / void`；每个场景 1–3 层噪声床（不同频段带通/低通 + 独立 LFO 起伏 + 立体声位置）+ 随机细节事件。
- 场景解析顺序：`plan.scene` → `score.scene` → `reason` → 文本关键词正则 → 档位兜底（daily→interior、suspense→street、unease→wind、horror→dread、urgency→storm、sorrow→rain、awe→wind、aftermath→rain）。
- 细节事件：雨滴打在不同表面（`drop`/`drip`）、远雷（`thunder`，40–120Hz 滚动噪声 + 长衰减）、车流远近（`car`，带通噪声 + 声像横移 + 多普勒式频移）、火焰爆裂（`crackle`）、阵风（`gust`）、木板吱呀（`creak`）、远处人声（`murmur`）。
- 混音：每个场景一条 `SceneBus`，经 `masterGain → 90Hz 高通 → 1.1kHz 轻削 -3.5dB → 8.5kHz 低通` 汇入与 BGM 相同的 `mixInput`（限幅器 → EQ → 饱和 → 主增益），因此共享同一套总线保护，且不会与 BGM 的中低频打架。
- 交叉淡化：换场使用等功率 `sin/cos`，默认 2.2 秒，不做硬切；`stop()` 默认 0.7 秒淡出。
- 与配乐的关系：配乐播放时环境音自动 `×0.62` 让位（`setMusicActive`）；配乐静音不再连带关闭环境音（`musicMuteGain` 与 `masterTargetGain` 已分离）。
- 降级：没有 `AudioContext`、没有 `TrpgImmersiveMusicModule.audioGraph()` 或自动播放被拦截时，只记录待播场景，不抛错；首次用户手势后自动拉起。
- 火焰/人声按设计可以走 CC0 采样，但为保证离线可用与零版权风险，本版用程序化爆裂/低语噪声实现，未引入任何网络下载；接口层仍是场景 + 事件，后续替换采样不需要改调用方。

### 四、P1 电影音色

- 新增 `heartbeat`（62→44Hz 双 thump）、`clock`（2.8kHz 噪声点 + 1.8kHz ping）、`texture`（3 秒无缝 grain cloud）、`impact`（1.6 秒低频冲击 + 噪声裂口）、`riser`（4 秒一阶状态变量滤波扫频）、`fmBell`（非整数比 3.5，指数衰减），以及 drone 的低通锯齿微失谐层。
- 实时/预渲染分工：drone、pad、ostinato、时钟、心跳、FM 钟为实时合成；grain、riser、impact 为初始化时预渲染 buffer（`WeakMap<AudioContext, TextureBuffers>`，随上下文释放）。
- 低性能档（`quality = 2`）自动关闭颗粒、riser、impact 与 LFO，只保留正弦/三角骨架。

## 修复程序化配乐「每小节之间有明显间隔」

改动时间：2026-11-07（Asia/Shanghai）

### 版本

- 继续并入 **1.0.1**（`v1.0.1` 尚未打 tag、也未创建 GitHub Release）。

### 根因

- 持续声部（pad / strings / organ / choir）此前**每小节重新触发一次**：单条音符只渲染 `1.04 × barDuration`，释放段从结尾前 0.5–0.7 秒开始。旧和弦在小节线处只剩峰值的 0.03%–0.39%（daily 78 BPM 为 0.08%，horror 44 BPM 为 0.39%，urgency 132 BPM 为 0.03%），下一小节又从 `0.0001` 重新起音，于是每个小节线都出现一次可听的音量凹槽，听感就是「每小节断一下」。这不是播放器换段重建节点，也不是 `setTimeout` 抖动。
- 低音每小节只保持 `0.96 × barDuration`，小节末尾天然留下约 4% 的真空；持续低频因此也跟着小节脉动。
- 同和弦跨小节重复起音会让多路振荡器相位不一致，叠加后产生「呼吸/泵动」，进一步放大断句感。
- A/B 总线切换原为线性淡化，中点功率下降约 3dB；这属于段落切换的次要问题，但会与逐小节凹槽叠加。
- 调度器本身已经是基于 `AudioContext.currentTime` 的 lookahead（提前 2.2s、每 220ms 排一次），段落切换也按小节量化；这两项不是本次根因。

### 修复

- `music-engine.ts` 新增「和弦 + 配器」段落键：同一段落内持续声部只在**和弦真正变化**时起音一次，一条长音覆盖整个和弦时值（bed 4 小节 / rise 2 / tail 3 / climax 1），不再逐小节重触发。
- 长音在段落线后额外保留 0.3–0.75 秒尾巴；和弦切换时旧声部用等功率 `cos` 收尾、新声部用等功率 `sin` 起音，两者功率互补，不再出现 6dB 凹槽。首次进入或留白之后仍保留原本的 0.3–0.8 秒慢起音，音色不变。
- 临近 `void` 留白的最后一条长音提前 0.45 小节收干净，保留原有「留白即重音」的编排；留白小节会清空延续状态，休止后的同和弦仍会重新起音。
- 低音按根音跨小节延续（紧迫档的脉冲低音保持原样）；过渡垫（`playBridge`）增加尾巴，玩家中途加入时与下一小节等功率接力。
- 同和弦跨段时按 ±6 半音就近转位（voice leading），只改变排列、不改变和弦级数与走向，避免整块 pad 平行大跳。
- 持续声部保持既有的 2.2s lookahead + 音频时钟调度；长音以单次 Web Audio 自动化事件渲染，不引入预渲染 buffer，因此没有额外启动延迟或内存开销。
- 混响发送仍位于总线增益之前，A/B 交叉淡化时旧总线的混响尾音继续自然衰减。
- `music-voices.ts` 为 pad / strings / organ / choir / bass 增加可选释放长度与等功率包络；默认调用路径（动机等瞬态声部）保持原包络形状。

## 平台用途选择器：对话与配图可落到不同平台

改动时间：2026-11-07（Asia/Shanghai）

### 版本

- 并入 **1.0.1**（不打 tag、不出包）。

### 用途清单与调用点

每个 AI 平台新增 `capabilities` 多选字段，只列真实调用点：

| 用途 | 标识 | 调用点 |
| --- | --- | --- |
| 对话 / KP | `chat` | 房间与站点对话主链路 `routes/chat.py`、角色卡生成 `character_ai.py`、叙事续写 `agents/narrative/generate_ai.py` |
| 配图判断 | `illustration` | `immersive/illustration_director.py`（AI KP 判断是否配图并生成提示词；实际渲染仍走生图平台表） |
| 音乐导演 | `music_director` | `immersive/director.py`（实时配乐的后台 LLM 精修） |
| 剧本创建 | `scenario` | 剧本导入转换 `routes/scenarios.py`、模块摘要 `routes/scenario_summary.py`、AI 导入 `scenario_import_ai.py` |
| 站点 Agent | `agent` | `site_agent.py` 站点助手对话与工具调用 |
| 语音配音 | `voice` | 预留用途；当前浏览器本地配音不经过 AI 平台，云端语音尚未接入 |

Embedding 走独立的向量/检索体系，不属于 AI 平台文本调用，未加入用途清单。

### 解析规则

- 新增 `backend/trpg_server/ai_platform_resolver.py`：按 `order` 升序遍历平台，依次校验「已启用 → 用途包含本次用途 → 配置完整且近期无失败记录」，第一个三项都满足的平台即为本次目标。
- 对话、配图、音乐导演、剧本、Agent 各自用独立 `purpose` 解析；同一份平台顺序下，对话可以落到 A 平台、配图落到 B 平台，互不影响。
- 平台顺序复用「模型设置」里已有的拖动排序（`order` + `POST /api/config/aiplatform/order`），卡片自上而下即加载优先级。

### 降级与健康缓存参数

- 不做主动探测：只有真实调用失败才写入短期失败记忆，避免每个请求额外打一次接口。
- 普通错误（超时、5xx、响应非法、空正文）：TTL **60 秒**；`401/403/404`（鉴权或地址错误）：TTL **300 秒**。
- TTL 内该平台在对应用途上被跳过，请求顺延到下一个候选；TTL 到期后自动半开重试，调用成功立即清除记录并恢复。
- 失败记录按「平台 + 用途」隔离：配图失败不会让同一平台的对话被跳过。
- 房间对话、配图判断、音乐导演、剧本导入/摘要、站点 Agent 均在单个平台失败后顺延到下一个，全部失败才返回错误。

### 旧配置默认值

- 缺少 `capabilities` 字段时按 `chat, illustration, music_director, scenario, agent` 处理；显式空数组表示「不参与任何用途」。
- 理由：升级前所有启用平台都参与过「取第一个启用平台」的文本补全，默认放行这五项可以保证升级后对话/配图/剧本不中断；语音是本版新增的占位用途，历史上没有任何平台承担，因此不默认勾选，避免把文本平台误当成语音服务。

### 前端

- 「模型设置 → 平台卡片」新增用途 chip 行：选中态高亮，点击即切换并保存；卡片上直接可见每个平台声明了哪些用途。
- 平台用途选项与后端 `CAPABILITY_OPTIONS` 保持一致；`GET /api/config/aiplatform` 现在同时返回 `capability_options` 供其他前端复用。
- `POST /api/config/aiplatform/<platform>` 保存时归一化用途（去重、丢弃未知值）；旧配置读取时由后端补默认值，前端不会把缺失字段误显示为空。

### 二、新增房间命令

- `immersive music search [场景] [--tags=a,b] [--profile=x] [--intensity=y]`：重新检索外链 BGM（默认绕过查询缓存，`--cache` 允许命中缓存）；引擎不是 `external`、档位/强度非法时给出明确提示。
- `immersive music switch [序号|track_key|标题]`：在最近一次检索结果中切换曲目；省略参数或 `immersive music next` 表示换一首。
- `immersive music on|off`：房间级配乐总开关（与用户个人本地开关相互独立）。
- `immersive music show`：补充展示当前引擎与原因、档位、当前外链曲目（含许可与时间）与底床状态。
- 以上命令均受房间控制台既有权限门控（默认仅房间所有者/管理员或站点管理员/所有者）。

### 三、手动插入叙事块
