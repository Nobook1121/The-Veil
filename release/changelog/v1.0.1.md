### 一、音乐长时间停在一个音上：量化与修复

- **旧实现的数据**（Node 复算真实编排产物，非估算）：和声节奏固定为 bed 4 小节 / rise 2 / tail 3 / climax 1。horror 44 BPM 每小节 5.45 秒，bed 段一个和弦持续 **21.8 秒**，实测最长同和弦连续 **32.7 秒**；所有档位最长同音响 12.8–28.0 秒、同和弦 18.5–33.1 秒。段内低音在 bed/tail 整段锁在同一个 pedal 上，horror 达 43.6 秒。
- **根因**：和声节奏以「小节」为单位写死，速度越慢、停滞越久；bed/tail 的低音整段是单一 pedal；段落内部没有内声部，pad 之外没有推进层。
- **修复**：
  - 和声节奏改为按秒折算：`HARMONY_SECONDS = { bed: 6, rise: 4.5, climax: 3, void: 99, tail: 5 }`，`rhythm = clamp(round(target / barDuration), 1, 4)`；并新增「同和弦最多重抽 4 次」的约束，避免进行本身退化成连续同和弦。
  - 内声部 `MotionPlan`：无前景动机的小节进入 2–3 个和弦音（bed 三音→五音、rise 级进上行、climax 五音→三音→根音、tail 回落），走 `pluck`/`organ`/`bell`，增益 0.085–0.105，只在后半小节出现，不抢前景。
  - 低频 `PulsePlan`：suspense/unease 用时钟点，horror/aftermath 用 62→44Hz 双 thump 心跳，留白段保留一条极稀疏心跳；urgency 保持 16 分 ostinato 不叠心跳。
  - bass 的 pedal 改为「2 小节一块」在主音与属音之间交替（I–V pedal），不再整段锁死一个低音。
  - 颗粒织体 `texture`、高潮 `impact`、进入高潮前的 `riser` 作为预渲染 buffer 层接入（见「四」）。
- **修复后数据**：同和弦最长 daily 9.23s / suspense 11.61s / unease 8.89s / horror 10.91s / urgency 5.45s / sorrow 8.28s / awe 10.59s / aftermath 8.57s；同低音最长 10.91–13.33s（旧 horror 43.6s）；段内同音响最长 5.75–11.66s。

### 二、播放一段时间后戛然而止：根因与证据

- **根因 1（主因）**：`void` 留白段旧实现被强制 8 小节。horror 每小节 5.45 秒，等于 **43.64 秒**几乎没有和声：段内全部 `chord = null`（没有 pad、没有低音），动态曲线降到 0.06，并且每 3 小节还有一处 `silence` 全静音；`playMotif` 当时被 `bar.chord` 守卫整段丢弃，只有极轻的 drone 和偶发钟声。这就是「播到一段时间突然没了、隔很久才回来」——按 horror 185.5 秒一轮循环算，每轮约在第 131–175 秒出现。
- **根因 2（换歌/中途加入）**：`playBridge` 只在「目标小节本身有和弦」时铺过渡垫。共享播放位置如果正好落在留白小节，旧总线此时已经淡出，新总线整小节不发声，最多再静音 5.45 秒。
- **排除项**：调度器没有断供。按 220ms tick、2.2s lookahead 复刻 `scheduleUntil` 推进 2 轮循环：horror 1686 个窗口、共排 69 小节，提前量始终在 0–5.45 秒之间，从未为负（没有跳小节），也没有连续空窗；`AudioContext` 挂起不在本次复现路径内，但已补上恢复分支。
- **修复**：
  - `void` 按秒收敛：`BREATH_SECONDS = 7.5`，`clamp(round(7.5 / barDuration), 2, 4)` 小节，horror 由 43.64s 降到 **10.91s**，其余档位 6.15–8.89s。
  - 留白不再有 `silence` 小节：改为「抽掉和弦 + 总线压到约 -17dB + 保留心跳/颗粒/钟声/混响」，任何时刻都有声，不会出现硬静音。
  - 总线电平：无和弦小节改用 `base × (0.10 + dynamic × 0.5)`，有和弦仍是 `base × (0.22 + dynamic × 0.85)`；去掉旧的 void `+0.12` 补偿。
  - `playBridge` 找不到和弦时向前回溯最近一个有声小节，仍找不到则用主音三和弦兜底，保证换歌不会先静音一小节。
  - 换歌切入位置避开无和弦小节：`audibleOrdinal()` 向前顺延到最近的有声小节（所有客户端算法一致，不破坏房间同步）。
  - 健康检查：`AudioContext` 处于 `suspended` 时 `resume()` 并跳过本拍；所有总线结束但仍有活动 plan 时重建总线，而不是让调度器静默退出。
- **修复后数据**：全部可听事件（pad 覆盖 + 动机/内声部/心跳/钟声/颗粒，事件按 0.28s 计）之间的最大空档 daily 2.03s / suspense 2.62s / unease 3.05s / horror 3.81s / urgency 1.54s / sorrow 2.82s / awe 2.37s / aftermath 2.93s（旧 horror 42.9s）。留白段的最大「无和声」时长 5.66–10.16s，但期间仍有织体、心跳与混响。

### 三、环境音（P2）落地

- 新增 `ambient-engine.ts`，**零音频资源**：全部由噪声整形合成。
- 9 个场景：`interior / street / storm / wind / dread / rain / fire / forest / void`；每个场景 1–3 层噪声床（不同频段带通/低通 + 独立 LFO 起伏 + 立体声位置）+ 随机细节事件。
- 场景解析顺序：`plan.scene` → `score.scene` → `reason` → 文本关键词正则 → 档位兜底（daily→interior、suspense→street、unease→wind、horror→dread、urgency→storm、sorrow→rain、awe→wind、aftermath→rain）。
- 细节事件：雨滴打在不同表面（`drop`/`drip`）、远雷（`thunder`，40–120Hz 滚动噪声 + 长衰减）、车流远近（`car`，带通噪声 + 声像横移 + 多普勒式频移）、火焰爆裂（`crackle`）、阵风（`gust`）、木板吱呀（`creak`）、远处人声（`murmur`）。
- 混音：每个场景一条 `SceneBus`，经 `masterGain → 90Hz 高通 → 1.1kHz 轻削 -3.5dB → 8.5kHz 低通` 汇入与 BGM 相同的 `mixInput`（限幅器 → EQ → 饱和 → 主增益），因此共享同一套总线保护，且不会与 BGM 的中低频打架。
- 交叉淡化：换场使用等功率 `sin/cos`，默认 2.2 秒，不做硬切；`stop()` 默认 0.7 秒淡出。
- 与配乐的关系：配乐播放时环境音自动 `×0.62` 让位（`setMusicActive`）；配乐静音不再连带关闭环境音（`musicMuteGain` 与 `masterTargetGain` 已分离）。
- 降级：没有 `AudioContext`、没有 `TrpgImmersiveMusicModule.audioGraph()` 或自动播放被拦截时，只记录待播场景，不抛错；首次用户手势后自动拉起。
- 火焰/人声按设计可以走 CC0 采样，但为保证离线可用与零版权风险，本版用程序化爆裂/低语噪声实现，未引入任何网络下载；接口层仍是场景 + 事件，后续替换采样不需要改调用方。

### 四、P1 电影音色

- 新增 `heartbeat`（62→44Hz 双 thump）、`clock`（2.8kHz 噪声点 + 1.8kHz ping）、`texture`（3 秒无缝 grain cloud）、`impact`（1.6 秒低频冲击 + 噪声裂口）、`riser`（4 秒一阶状态变量滤波扫频）、`fmBell`（非整数比 3.5，指数衰减），以及 drone 的低通锯齿微失谐层。
- 实时/预渲染分工：drone、pad、ostinato、时钟、心跳、FM 钟为实时合成；grain、riser、impact 为初始化时预渲染 buffer（`WeakMap<AudioContext, TextureBuffers>`，随上下文释放）。
- 低性能档（`quality = 2`）自动关闭颗粒、riser、impact 与 LFO，只保留正弦/三角骨架。

### 新暴露的前端 API（供设置面板/悬浮球那条线接入）

```ts

```

### 仍需人耳确认

1. horror/unease 等慢速档位在 10–13 秒同和弦下的「推进感」是否足够，内声部是否被 pad 掩蔽。

6. 限幅器（-8dB / 4:1）在 pad + 环境音 + 语音 ducking 同时叠加时是否泵动。

## 修复程序化配乐「每小节之间有明显间隔」

改动时间：2026-11-07（Asia/Shanghai）

### 版本

- 继续并入 **1.0.1**（`v1.0.1` 尚未打 tag、也未创建 GitHub Release）。

### 根因

- 持续声部（pad / strings / organ / choir）此前**每小节重新触发一次**：单条音符只渲染 `1.04 × barDuration`，释放段从结尾前 0.5–0.7 秒开始。旧和弦在小节线处只剩峰值的 0.03%–0.39%（daily 78 BPM 为 0.08%，horror 44 BPM 为 0.39%，urgency 132 BPM 为 0.03%），下一小节又从 `0.0001` 重新起音，于是每个小节线都出现一次可听的音量凹槽，听感就是「每小节断一下」。这不是播放器换段重建节点，也不是 `setTimeout` 抖动。
- 低音每小节只保持 `0.96 × barDuration`，小节末尾天然留下约 4% 的真空；持续低频因此也跟着小节脉动。
- 同和弦跨小节重复起音会让多路振荡器相位不一致，叠加后产生「呼吸/泵动」，进一步放大断句感。
- A/B 总线切换原为线性淡化，中点功率下降约 3dB；这属于段落切换的次要问题，但会与逐小节凹槽叠加。
- 调度器本身已经是基于 `AudioContext.currentTime` 的 lookahead（提前 2.2s、每 220ms 排一次），段落切换也按小节量化；这两项不是本次根因。

### 修复

- `music-engine.ts` 新增「和弦 + 配器」段落键：同一段落内持续声部只在**和弦真正变化**时起音一次，一条长音覆盖整个和弦时值（bed 4 小节 / rise 2 / tail 3 / climax 1），不再逐小节重触发。
- 长音在段落线后额外保留 0.3–0.75 秒尾巴；和弦切换时旧声部用等功率 `cos` 收尾、新声部用等功率 `sin` 起音，两者功率互补，不再出现 6dB 凹槽。首次进入或留白之后仍保留原本的 0.3–0.8 秒慢起音，音色不变。
- 临近 `void` 留白的最后一条长音提前 0.45 小节收干净，保留原有「留白即重音」的编排；留白小节会清空延续状态，休止后的同和弦仍会重新起音。
- 低音按根音跨小节延续（紧迫档的脉冲低音保持原样）；过渡垫（`playBridge`）增加尾巴，玩家中途加入时与下一小节等功率接力。
- 同和弦跨段时按 ±6 半音就近转位（voice leading），只改变排列、不改变和弦级数与走向，避免整块 pad 平行大跳。
- 持续声部保持既有的 2.2s lookahead + 音频时钟调度；长音以单次 Web Audio 自动化事件渲染，不引入预渲染 buffer，因此没有额外启动延迟或内存开销。
- 混响发送仍位于总线增益之前，A/B 交叉淡化时旧总线的混响尾音继续自然衰减。
- `music-voices.ts` 为 pad / strings / organ / choir / bass 增加可选释放长度与等功率包络；默认调用路径（动机等瞬态声部）保持原包络形状。

## 修复发布包首次部署可能不进入安装向导

改动时间：2026-11-07（Asia/Shanghai）

### 版本

- 继续并入 **1.0.1**（截至本次修复，`v1.0.1` 尚未打 tag、也未创建 GitHub Release）。

### 根因

- 实际核对 `release/the-veil-v1.0.0.zip`（SHA256 与 GitHub Release 资产一致）：包内既没有 `data/config`，也没有 `data/users` 或 `data/runtime`；`config/templates/general.toml` 的 `[site] setup_dismissed = false`。用该包在干净目录直接启动，`GET /api/setup/status` 返回 `owner_exists=false`、`setup_dismissed=false`、`setup_required=true`，说明发布包内容本身没有丢向导。
- 真正的第二个首启判断在浏览器：旧版 `frontend/src/app/setup-wizard.ts` 额外读取 `localStorage["trpg_setup_dismissed"]`，命中就跳过向导。这个标记不随发布包重置，只要同一浏览器在此前的实例里点过「跳过全部引导」，之后解压任何新包都会「首次部署却不出向导」，且服务端的 `setup_required=true` 被前端忽略。
- 同时确认项目里已不存在 `data/config/site.json`：分层配置迁移后，首启状态的真实来源是首次启动从 `config/templates/general.toml` 复制出的 `data/config/general.toml` 的 `[site] setup_dismissed`，并由 `/api/setup/status` 与「是否存在 OWNER」共同判定。

### 修复

- `frontend/src/app/setup-wizard.ts`：移除 `trpg_setup_dismissed` 本地标记的读取与写入，向导是否出现完全以服务端 `setup_required && owner_exists !== true` 为准；跳过动作仍由 `/api/setup/dismiss` 持久化到服务端配置。
- `scripts/package-release.ps1`：新增首启校验 `Assert-FirstRunReady`（暂存目录）与 `Assert-ZipFirstRunReady`（最终 zip）。断言配置模板 `[site] setup_dismissed = false`、包内不存在 `data/config`、`data/runtime`、`data/users`、`backend/data` 与任何 `users.sqlite3`/`users.json`，并确认 `dist/public/js/setup-wizard.js` 存在；任一不满足即删除坏包、打印缺失项并以非零码退出。
- 新增 `tests/test_release_first_run.py`：固化「模板必须关闭 setup_dismissed」「空配置目录首次种子必须为 false」「干净部署状态接口必须 setup_required=true」「打包脚本必须保留首启校验」四条规则。
- `backend/trpg_server/settings.py`、`backend/trpg_server/routes/bgm.py`、`frontend/src/locales/{zh_cn,en_us}.json`、`frontend/src/index/fragments/03-room-tools-auth-settings.html`、`frontend/src/types/bgm.d.ts`、`backend/trpg_server/routes/rooms.py`：把「内置音乐随程序分发」改为事实表述——内置曲目位于 `data/assets/bgm`，发布包不随包分发，目录缺省时曲库为空且不影响运行。
