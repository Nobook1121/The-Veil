# v0.5.2b

发布日期：（待发布）

变更时间：2026-10-21 16:45

本次更新新增「网站 Agent」：登录用户可通过右下角悬浮球、可拖拽窗口或独立 Agent 页，用自然语言查询角色卡、剧本、房间资料与权限信息；所有写操作先生成待确认卡片，用户确认后才由服务端重新鉴权并执行。原「小工具」页移除，侧边栏入口改为 Agent。

## 网站 Agent（P0 基础设施）

- 新增权限节点 `agent.use`（默认授予 `USER` / `ADMIN` / `OWNER`）与内置角色 `site_agent`；旧角色配置在读取时自动补齐该角色。
- 新增 `site_agent_config.py`：从 `general.toml` 的 `[site_agent]` 读取启用开关、工具轮数、请求超时、历史条数、工具结果上限、每小时轮数、每日 token 预算、会话保留天数、操作有效期与会话/消息上限，并对数值做区间收敛。
- 新增 `site_agent_store.py`：按用户隔离的会话 JSON、待确认操作、JSONL 审计（按大小滚动）、逐日 token 用量、每小时轮数与每用户轮次锁；会话 ID 与操作 ID 使用固定前缀 + 随机串并做正则校验，阻断路径穿越。
- 新增 `site_agent_auth.py`：身份只来自服务端会话（角色以数据库为准），按「会话有效 → Agent 开关 → `agent.use` → 工具权限 → 房间成员范围 → 业务校验 → 写操作需确认」的顺序授权。
- 新增 `site_agent_prompt.py`：系统提示词只描述规则，不承载权限；剧本、角色卡、用户名、聊天与记忆等文本统一包裹在随机边界的不可信数据块中；注入特征仅记录审计与提示，不自动改写。
- 新增工具注册表 `site_agent_tools/`：参数按 JSON Schema 白名单清洗，身份字段（`user_id` / `role` / `permissions` 等）与路径/命令类字段一律丢弃。只读工具包含 `characters.list/get`、`scenarios.list/get`、`room.get_room_snapshot/get_character_record/get_memory/scenario_search`、`utilities.dice_roll/random_choice/date_math`。
- 新增编排层 `site_agent.py` 与 `routes/site_agent.py`：每轮固定记录 prompt / completion / cached / total tokens 到助手消息与审计；支持按平台顺序故障转移；超时、轮数、每日预算与消息长度均有明确错误提示。

## 写操作与领域服务（P1 / P2）

- 新增 `character_service.py` 与 `scenario_service.py`：角色卡与剧本的保存逻辑从路由中抽出，路由与 Agent 共用同一套校验、版本与知识库索引逻辑，避免两条写路径分叉。
- 新增写工具 `characters.save`、`scenarios.save`、`permissions.set_role_permission`、`users.set_role/set_status/force_password_reset`：只生成 `pending_action` 预览附件，不直接落库；确认时重新鉴权并检查操作有效期（默认 5 分钟）。
- 权限敏感规则：`OWNER` 专属节点仅所有者可改；`ADMIN` 只能修改 `USER` 行且不能自授 `agent.use`；用户管理不能操作自己、不能操作更高权限账号、不能把账号提升到超过自身权限，最后一个 `OWNER` 不能被停用或封禁。
- 角色卡保存强制非管理员只能写入自己的角色；剧本写入复用既有的所有者/权限检查与版本递增。
