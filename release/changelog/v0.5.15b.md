# v0.5.15b · 实时配乐共享时钟与抗短循环编排

变更时间：2026-11-04 11:38（补录 2026-11-03 23:35–23:53 已完成但尚未记录的改动）

## 结论

- 「同一 cue 被反复从开头重放」的问题从三处根因同时修复：段落不再按回合硬切、强度变化不再被误判为换歌、换谱后从当前戏剧阶段的小节切入。
- 房间内所有玩家共享一条以小节计的播放位置，新玩家加入时按当前进度补发，不再从 cue 开头听起。

## 后端

- `backend/trpg_server/immersive/music.py`：移除 `SECTION_TURNS = 4` 的回合段落推进，段落只由内容真正变化（换档位 / 手动指令 / 导演新谱）触发。
- 新增房间级共享时钟字段 `cue_epoch`、`cue_key`、`cue_position_bars`、`cue_bar_seconds`、`cue_updated_at`：同一份谱面只累加播放位置，换谱才开启新 epoch。
- 新增 `_score_identity(score)`：谱面身份只包含调式、配器、和弦、动机变体、段落形状、动态与 pedal，**排除 tempo**，避免强度变化导致整首重放。
- 新增 `current_sync()` / `current_payload()`：只读推算当前位置供新玩家加入时补发；`plan_music` / `apply_director` 落盘前统一调用 `_advance_cue()` 推进时钟并保留 `cue_payload`。
- AI 导演不可用（未配置 / 预算耗尽 / 校验失败）时改用 `build_auto_score` 接管，保证「叙事 → 配乐」始终拿到完整乐谱，而不是只有氛围档位参数。

## 前端

- `frontend/src/app/immersive/music-engine.ts`：新增 `contentSignature()`，由档位、基准种子（去掉段落 `:N` 后缀）、导演指纹与乐谱指纹组成；强度、音量、tempo、section 序号不再触发音乐总线重建。
- 换谱时起始位置优先采用服务端 `sync.position_bars`（含服务端时间基准），其次沿用旧总线本地进度；新总线通过 `startKind` + `sectionStartBar()` 从当前戏剧阶段对应小节切入，不再固定从第 0 小节重放。
- 新增 `SYNC_DRIFT_LIMIT_BARS = 2` 与服务端/本地时钟漂移校正，跨端进度不会越走越偏。
- `frontend/src/app/immersive/music-arranger.ts`：ostinato 每小节轮换音型起点、每 4 小节反向、每 8 小节换八度，并叠加按小节错位的卡农层；动机族在同一循环内优先使用未出现过的族，复用旧族时做逆行/倒影，避免同一句旋律跨段落原样重复；段落间继续以枢轴和弦或 pedal point 衔接。
